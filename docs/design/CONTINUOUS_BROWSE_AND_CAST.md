# 连续浏览与投屏产品优化

2026-10-21。0.34.0用户确认A–F功能组通过，同时提出五项体验缺陷；通过结果与缺陷并列保留。本轮只交付这五项完整优化，不扩展直播、双账号或真实账号写入。

沿用1920×1080、深蓝背景#0C1524/面板#16263B/卡片#20354D、正文#F4F7FB/辅助#A9BAD0/焦点#FB7299。标题48px、正文30px、辅助24–26px；中文系统无衬线，时间用等宽数字。特色是“当前内容始终在场”：焦点移动、加载、阅读与投屏状态变化都保留明确落点，不靠页面跳转或装饰大背景表达。

```
[主导航]  [栏目/筛选]              [刷新]
          卡片 卡片 卡片 卡片
          卡片 卡片 卡片 卡片  ← 方向下连续浏览
          正在加载 / 已到底 / 可继续加载（失败恢复）

投屏： [接收器图形] BiliSofa        同一网络
       未开启 / 等待手机 / 连接中   哔哩哔哩视频内 TV
       [开始接收/结束/重新接收]    选择 BiliSofa
```

首页侧栏每次向右解析当前可见且可用的内容入口，隐藏/失效的继续观看锚点不得截断路径。首页、统一搜索、关注/已追、我的/收藏内容共用有界窗口：最多三批十二张DOM卡，接近末行预取，向下到边缘继续，向上可回读已移出窗口的前批；底部保留显式失败恢复，取消/来源切换拒绝旧回包。网络每批四项仍遵守现有合同，UI不再暴露上一页/下一页。源端无更多/范围限制如实展示，不一次下载全库。内存窗口裁剪后释放封面ObjectURL，不积累离屏图片。

关注更新只对源端提供的、经严格校验的公开视频BV显示播放；不以标题搜索首项替代目标，不把专栏或无ID摘要伪装成可播内容。公开视频标识允许进入DTO，原链接、私密游标、账号凭据仍不跨UI。完整动态/UP来源阻塞保持。

队列复用完整VOD工作区的控制栏/更多、轨道、倍速、叠加阅读和返回；后继项等前一媒体真实关闭后打开，保留原BV＋P顺序、逐P续播和显式连播决定。没有源时仍走原错误/回退合同。

投屏目的页在用户允许前不监听。等待层显示接收器名称、手机端操作与前台限制；媒体就绪后才显示全屏播放控制，结束/错误后回等待或可恢复状态，Home停止且重开需再次允许。清晰区分连接状态与手机/遥控控制权；不新增AirPlay协议、镜像、自动后台接收或账号关联。

## 一手参考与项目取舍

- [Samsung内容分类与方向导航](https://developer.samsung.com/smarttv/design/apps-screen.html)：避免复杂层级阻碍分类与内容互达。
- [Google TV焦点驱动滚动](https://developer.android.com/training/tv/playback/compose/lists?authuser=96)：焦点目标保持可见；仅借鉴交互原则，不在Tizen引入Compose。
- [Netflix当前TV导航](https://help.netflix.com/en/node/321880164349028)：直接返回主导航、个人内容集中。BiliSofa保留现有侧栏，不声称复制其顶部菜单。
- [Apple投屏步骤](https://support.apple.com/en-us/102661)：同网、选择设备、明确停止。BiliSofa仅借鉴状态和引导，仍为官方B站App内TV兼容接收。

这些来源不证明当前YouTube/B站电视版的逐页实际UI，也不证明本机声画/性能；不凭印象宣称复刻。完成后以本地回归、实际包身份和一次受影响电视清单分别交付。
