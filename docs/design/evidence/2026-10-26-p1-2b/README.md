# ADR-113 P1-2b 设备验证：账号并入设置与按键开销（0.62.0）

2026-10-26。用户授权签名、安装0.62.0，在电视上实看设置里的账号组和侧栏，并测首页与播放器的按键响应，与0.61.1对比。

- **设备**：Samsung UN58U8200FFXZC，Tizen 9.0，登录状态（启动选择页选已有账号）。
- **包**：未签名`ca3a311b…fd6a`，签名`6f9f7bbe…3864`（只签一次，证书预检PASS，权限不变）。
- **安装**：升级安装、启动均platformSuccess（一次，不清数据）。

## 实看（用户确认）

用户从电视主页正常打开0.62.0，选自己的账号后逐项确认都符合：

1. 侧栏只有7项（首页、搜索、关注、番剧影视、我的、投屏、设置），没有“账号”；“设置”与上面几项之间有间隔。
2. “设置”左列第一项是“账号”且默认选中；右侧是当前身份、电视保存的会话和扫码登录。
3. 右键进入账号操作、左键回到“账号”；下键切到“播放”等其他分组正常。

没有执行“使用游客身份”或扫码。

## 按键响应

**首页**：方法、脚本与0.61.1数据见[P2a设备证据](../2026-10-26-p2a-device/README.md)（`keyspeed.mjs`）。

- 新启动的应用，“热门视频”行右10左10。
- 快：间隔150 ms，5轮；慢：间隔600 ms，3轮。

**播放器**：[playerspeed.mjs](playerspeed.mjs)。

- 短按OK播放“热门视频”第一个视频，起播后每轮做两件事：
  - 控制层自行隐藏后，10 s不按键，记录帧间隔；这时只有200 ms的刷新在跑；
  - 唤出控制层，在主行右6左6（间隔400 ms），记录`keydown`到其后第二帧的时间。
- 3轮。0.61.1与0.62.0各自从新启动测一次。
- 只记录时间、次数和焦点是否移动，不记录标题与编号。

| 条件 | 0.61.1 | 0.62.0 |
| --- | --- | --- |
| 首页 快：中位数 / p95 / 最大 | 33 / 49 / 60 ms | 32 / 52 / 62 ms |
| 首页 快：每轮>50 ms帧 | 3.2 | 4.4 |
| 首页 慢：中位数 / p95 / 最大 | 30 / 34 / 36 ms | 29 / 34 / 65 ms |
| 首页 慢：每轮>50 ms帧 | 1.3 | 2.3 |
| 播放器主行：中位数 / p95 / 最大（36次移动） | 26 / 33 / 36 ms | 24 / 36 / 36 ms |
| 播放器控制层隐藏10 s×3：>20 ms帧 / 最长帧 | 0 / 16.8 ms | 0 / 16.8 ms |

结论：

- 两个版本都没有超过200 ms的按键。
- 中位数相差1–2 ms，长帧次数相差每轮1次左右，都在轮与轮之间的波动范围内。
- 播放器控制层隐藏时，两个版本都稳定在每帧16.8 ms，没有掉帧。

P1-2b的按键开销改动（只在值变化时写DOM、显式邻居不扫描整层、内容区焦点不扫描）在这台电视上**没有带来可测的响应变化**：0.61.1已经在一帧的量级，余量不在这些地方。这些改动保留，因为它们减少了无用的DOM写入与布局，但不能声称因此变快。

原始数据：`ks-0.62.0-*.json`、`ps-0.61.1.json`、`ps-0.62.0.json`。
