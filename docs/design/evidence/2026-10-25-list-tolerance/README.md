# ADR-111 设备验证：列表逐卡容错（0.58.0）

2026-10-25。用户授权签名、安装0.58.0，要求按ADR-111重复冷启动20次，确认“为你推荐”不再出现`invalid`。

- **设备**：Samsung UN58U8200FFXZC，Tizen 9.0，登录状态。
- **包**：0.58.0未签名`9c39202b…d056`，签名`96decd07…bd8`（证书预检PASS，权限不变）。升级安装、启动均platformSuccess（一次，不清数据）。

## 方法

与定位时相同，脚本为[cold.mjs](cold.mjs)：

- 通过Inspector重载页面，模拟冷启动（Worker与WASM重新创建）；
- “谁在观看”一出现就立即选择账号；
- 等“为你推荐”一行出结果，记录：
  - 卡片数；
  - 时长按未知显示（角标隐藏）的卡片数；
  - 失败时状态行的错误码。
- 页面加载前注入探针，挂在Worker上，只记录结果帧的固定字段：`type`、`operation`、`kind`、`code`、`detail`、`skipped`，不记录内容。

## 修复前（0.57.2）

定位用的原始记录：

- **重载复现**：[repro-0.57.2.json](repro-0.57.2.json)（8次中1次失败）。
- **字段检查**：[field-0.57.2.json](field-0.57.2.json)（11次中1次失败）。
  - 用[field.mjs](field.mjs)把调试器挂到账号内核Worker，在`parseRecommendationCard`抛错处暂停；
  - 只读字段的类型、长度、控制字符与格式标志；
  - 唯一不合格的字段是`durationSeconds = 166242`（约46小时）。
- **合计**：有记录的19次重载中2次失败（约11%）。此外，0.56.0与0.57.2调试启动后各自然出现过一次。
- **更正**：ADR-111背景原写“27次中3次”，是重复计数，已更正。

## 解读与局限

- 20次全部正常，没有再出现`invalid`。
- **统计上的局限**：按修复前约11%的失败率，连续20次都不失败的概率约为10%（0.89的20次方）。只看这20次，统计证据偏弱。修复的主要依据是机制：
  - 已定位到具体字段与上限；
  - 单元测试用166242 s的推荐卡做回归，修复后整批保留、该卡时长显示为未知。
- **第4次的“时长未知”卡片**：说明这条显示路径在设备上生效。但源数据没有记录，不能确定它的源时长是超过24 h（修复前会让整批失败），还是正好为0（修复前也能通过）。
- **未覆盖**：
  - 其他列表（热门、搜索、资料库）在设备上没有专门制造坏行；
  - “帮助与诊断”里的`list_items_skipped`事实，因为这20次没有发生跳过，没有在设备上见到。
