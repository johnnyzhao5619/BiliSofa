# ADR-115 设备验证：来源检查改回逐项检查与超长视频（0.63.0）

2026-10-26。用户授权签名、安装0.63.0，要求用一个超过24小时的视频验证播放、跳转、弹幕字幕和续播，并对比普通视频的起播耗时。

- **设备**：Samsung UN58U8200FFXZC，Tizen 9.0，登录状态（启动选择页选已有账号）。
- **包**：未签名`7c65c013…63b4`，签名`34a18c82…769f`（只签一次，证书预检PASS，权限不变）。
- **安装**：升级安装、启动均platformSuccess（一次，不清数据）。
- **调试启动前**：应用仍在后台运行，调试启动没有回应；用`sdb shell 0 kill`结束后再调试启动。

## 起播耗时

方法见[ab2.mjs](ab2.mjs)：由ADR-112的测量脚本改为从卡片直接播放开始计时（ADR-113起卡片按OK直接播放，不经过详情页）。

- 依次播放“为你推荐”前4个视频，记录：
  - 卡片到“正在获取播放源”；
  - 到“缓冲中”；
  - 到首帧；
  - 首帧到第一条弹幕（账号默认关弹幕，每次临时打开后恢复）；
  - 打开评论到第一张卡片。
- 只记录时间与阶段文字，不记录标题与编号。
- 0.62.0与0.63.0各自从新启动测一轮；0.63.0另补一轮（同一次启动的第二次播放，CDN与连接已热）。

| 条件 | 卡片→获取播放源 | 获取播放源→缓冲中 | 卡片→首帧 | 打开评论→首卡 |
| --- | --- | --- | --- | --- |
| 0.62.0（成对检查） | 3.0–3.4 s | 1.2–2.1 s | 8.1 / 9.4 / 10.6 / 11.1 s | 2.3–2.8 s |
| 0.63.0 第一轮（逐项检查） | 3.0–3.4 s | **9.7** / 1.7 / 2.5 / 1.6 s | **17.4** / 8.4 / 9.6 / 8.4 s | 2.3–3.2 s |
| 0.63.0 第二轮 | 3.2–3.5 s | 0.8–1.2 s | 7.4 / 7.6 / 7.8 / 8.0 s | 2.1–3.6 s |

结论：

- 除一次之外，逐项检查的起播与0.62.0持平或略快，第二轮整体更快；与ADR-112“成对检查没有可测收益”一致。
- 0.63.0第一轮第一个视频在“获取播放源→缓冲中”用了9.7 s，也就是来源检查这一段。这次没有读取“帮助与诊断”里的来源记录，原因未查明；同一视频在第二轮为0.85 s。按用户“之后遇到类似问题再调查”的决定（ADR-110），只记录不追查。
- 每个版本只测了4次，热身状态也不同，不足以给出变快或变慢的结论。

原始数据：`ab-0.62.0.json`、`ab-0.63.0.json`、`ab-0.63.0-b.json`。
