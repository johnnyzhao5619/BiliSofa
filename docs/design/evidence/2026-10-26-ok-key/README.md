# ADR-113 设备前提：OK键按住与松开的按键事件（0.59.0）

2026-10-26。P1-2a第一步：确认这台电视按住OK时的`keydown`连发，以及松开时的`keyup`，用来决定卡片长按的判定方式。

- **设备**：Samsung UN58U8200FFXZC，Tizen 9.0，原装遥控器；应用为已安装的0.59.0（调试启动）。
- **方法**：
  - 用[keys.mjs](keys.mjs)经Inspector在`window`捕获阶段注入监听，只记录OK（Enter）的`keydown`/`keyup`：`key`、`code`、`keyCode`、`repeat`与相对时间；
  - 记录期间OK键不交给应用，3分钟后自动解除；
  - 用户按要求短按、按住若干次。原始数据：[ok-key-events.json](ok-key-events.json)。

## 结果

| 按法 | 次数 | 按住时长（`keydown`到`keyup`） | 按住期间的`keydown`连发 |
| --- | --- | --- | --- |
| 短按 | 6 | 274–308 ms | 0 |
| 按住约2 s | 4 | 1938–2840 ms | 0 |

- 10次全部有`keyup`，`key`为`Enter`、`keyCode`为13。
- **按住OK时完全没有连发**（`repeat`始终为`false`，期间没有第二个`keydown`）。

## 结论

- **不能用“连发”判定长按**，ADR-113第1项写的后备方案在这台电视上不可行。
- **改用计时**：
  - 在`keydown`时开始计时；
  - 在阈值之前收到`keyup`判为短按；
  - 到阈值仍未松开就打开菜单，之后的`keyup`忽略。
- **阈值0.5 s**：比最长的一次自然短按（308 ms）多约190 ms余量。
- **短按改在`keyup`时响应**，比今天的按下即响应晚约0.3 s。为弥补这一点，在`keydown`时就开始预读播放（ADR-110），判为长按时取消。
