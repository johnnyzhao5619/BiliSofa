# ADR-109 设备验证：封面跨页保留与身份只核对一次（0.56.0）

2026-10-25。用户要求开始真机验证。先在已安装的0.54.0上测基线，再签名、升级安装0.56.0，按同样步骤测量。

- **设备**：Samsung UN58U8200FFXZC，Tizen 9.0。
- **包**：0.56.0未签名`40337650…a769`，签名`3fceda36…fcb5`（证书预检PASS，权限不变）。升级安装、启动均platformSuccess（一次，不清数据）；用户确认首页与“谁在观看”显示正常。

## 方法

沿用[ADR-108的Inspector方法](../2026-10-25-network-kernel/README.md)，脚本为[lifecycle.mjs](lifecycle.mjs)：

- 注入探针，统计Worker的创建次数和封面请求（`hdslb.com`）次数；
- 用点击与`Escape`（返回）走完各场景；
- 只记录耗时、计数与通过标志。

每个场景只测一次，结果有自然波动。

## 后台恢复：未能测量

- 按Home离开再回来，这一项本打算用页面内计时（[resume.mjs](resume.mjs)），但两次都没有取得数据：
  - 第一次：应用在后台时JavaScript暂停，Inspector轮询看不到隐藏状态；
  - 第二次改为页面内监听：用户按Home后，开发机与电视之间的sdb连接断开，重新连上后页面没有记录到任何可见性事件。
- 所以这一项在两个版本上都没有数据，**OPEN**。需要另一种方法：例如在“帮助与诊断”里显示应用自己记录的恢复耗时，不依赖调试连接。

## 对P0-3b的含义

- 返回与顶层切页现在都在0.1–0.5 s之间，而且不再发出网络请求，也不再重新下载封面。页面DOM保活要改动所有页面的生命周期假设，收益已经很小。
- **建议不做DOM保活**，P0-3b只保留“后台恢复”一项，等有了可靠的测量方法再决定。
