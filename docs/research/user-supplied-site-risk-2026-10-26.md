# 用户自行输入网站能否降低风险

调研日期：2026-10-26。问题：编译后的应用不预填 `www.bilibili.com`，让用户首次输入该域名作为启用功能的钥匙，是否可以规避风险？本页只评估方案，**不实现启用门槛，不改变 e7bc374 / 0.65.1 软件基线**。

后续实施：用户进一步明确选择配置化方案，源码候选按[ADR-119](../adr/119-user-selected-local-service-configuration.md)实现。以下保留调研当时的范围和法律分析；实现用户配置不表示上述授权风险消失。

## 结论

**仅把固定域名改为用户输入，不能据此认定接口、版权、合同或品牌风险得到实质消除。** 如果输入之后仍运行专门的 Bilibili 登录、签名、目录解析、媒体适配和互动模块，核心服务及行为没有变化。这是基于当前实现与官方条款的分析，不是法院对 BiliSofa 的裁判。

## 为什么不是“网址由谁填写”决定

| 方案 | 实际改变 | 仍需解决的边界 |
| --- | --- | --- |
| 固定字符串钥匙：仅接受 `www.bilibili.com` | 增加一次人工确认；对初始自动请求可能有影响 | 专用接口、内容处理、账号与平台关系仍相同；字符串不是授权凭证 |
| 用户输入域名，但程序自行补出 Bilibili 专用 API / WBI / 投屏路线 | 改配置来源，不改功能实质 | 不会把非官方客户端变成平台认可的官方途径；不能据此保证免责 |
| 真正通用浏览器：加载用户选择的官方页面，不内置特定平台适配 | 改变产品与技术角色，可能影响具体风险分析 | 页面 / 平台规则、内容权利、设备能力和实际功能仍适用；不是“必然无风险”，也不等同于当前 BiliSofa |
| 权利人 / 平台提供并授权的 API、SDK 或用户可证明有权的媒体输入 | 实质改变访问依据或内容权利来源 | 在取得的具体许可、用途和终端范围内执行，不能超出许可；依实际材料评估 |

官方[用户协议](https://www.bilibili.com/blackboard/protocal/licence.html) 1.2–1.3、5.6(3)所涉及的是服务使用途径和通过软件取得服务 / 内容 / 数据等行为；让用户输入域名本身不提供书面许可。8.1–8.6 涉及内容 / 软件 / 品牌权利，也不由输入框改变。现行版本与日期见[主评估](../BILIBILI_TERMS_RISK.md)。

## 与当前代码的关系

当前 `platform/wasm-network/src/identity.c`、公共 / 账号读取内核、播放 / 评论 / 互动模块含固定 API 路线，WBI、会话目的地、Cookie / CDN 范围、CSP / WARP 与本机媒体桥相互配合。只删 UI 中一个网址并不移除这些平台专用能力。

如果真的支持任意网站，还须重新设计来源合同、账号隔离、凭据去向、重定向 / 目的地限制与媒体安全，不能直接把用户输入拼成任意网络请求；否则增加凭据外泄或任意代理等安全风险。那是新的产品与架构变更，不能拿 0.65.1 原有证据和哈希沿用。

如果目的只是让用户知情，可以在未来设计“说明数据来源、账号风险、隐私与用户主动开启网络访问”的入口；其作用是知情与控制，不宣传为规避责任的技术钥匙。本轮没有修改应用来添加该入口。

## 学习、非营利与愿意下架的作用

[《著作权法》第二十四条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)对个人学习 / 研究等使用设有条件，仍要求不影响作品正常使用，也不能不合理损害权利人利益。不能从一句用途声明推出公开分发客户端及其全部行为当然获得豁免；个人观看、分发软件、平台服务合同是不同问题。

非营利可以如实陈述为运营事实，但不能替代平台许可或证明所有使用都不侵权。标准 MIT 对原创代码的许可保持不变，不因作者非营利而给贡献者追加“禁止商用”。

[《民法典》1195、1197 条](https://www.cac.gov.cn/2020-06/01/c_15925617772683196.htm)涉及网络侵权通知、必要措施及知情责任。愿意及时下架有助于建立响应机制，但是否适用特定责任规则仍取决于实际角色与事实，不能当作追溯免责保证。本项目的[权利联系声明](../../RIGHTS.md)应配合真正可用的入口和行动。

本研究没有对所有发行地法律给出结论，也没有获得平台书面意见。更有效的工作是准确披露行为、核对内容 / 接口 / 标识权限、限制实际风险、建立投诉响应并寻求所需授权，而不是将平台专用功能隐藏在字符串门槛之后。
