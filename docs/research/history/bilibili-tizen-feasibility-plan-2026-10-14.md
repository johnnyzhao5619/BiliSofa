# 三星 UN58U8200FFXZC：Bilibili 客户端可行性与实施方案

> 历史资料：评论/回复发布、编辑/删除及点播/直播弹幕发送已由用户于2026-10-14移出范围，现仅查看。当前合同见[PRD](../../PRD.md)和[ADR-003](../../adr/003-read-only-comments-danmaku.md)，下文旧写入条目不再是实施要求。

> 功能范围、电视交互、架构决策与分期已由 [实施方案 v2](bilibili-tizen-implementation-plan-v2-2026-10-14.md) 更新；本文件保留首轮平台调研依据。

调研日期：2026-10-14。范围：个人家庭使用、侧载到这台电视、以中国大陆版 bilibili.com 的观看功能为目标。若目标是国际版 bilibili.tv，需另做接口与内容调研。

## 结论与证据边界

可以开发三星 Tizen TV 应用，覆盖搜索、浏览、扫码登录、普通视频播放、多分 P、续播，以及逐步加入字幕、弹幕和评论阅读等功能。推荐先验证并复用现有开源客户端，再补齐功能。

这不等于可以仅凭三星手册稳定复制平板官方客户端。三星负责应用运行、遥控器、播放器和安装；Bilibili 的登录、内容接口、账户权益、风控和地域授权是另一组依赖。公开资料不足以保证所有功能长期可用，4K/会员内容/直播/投屏应分别验证。

本次完成了官方文档调研与开源项目源码审阅，未部署新应用、未使用账号调用 Bilibili 接口、未进行目标电视播放测试。源码存在与作者实测报告不是本机验收结果。

## 平台依据

- [三星加拿大产品页](https://www.samsung.com/ca/tvs/uhd-4k-tv/u8200f-58-inch-crystal-uhd-4k-smart-tv-un58u8200ffxzc/)确认型号为 2025 U8200F、One UI Tizen。官方[引擎规格](https://developer.samsung.com/smarttv/develop/specifications/web-engine-specifications.html)将 2025 年款映射至 Tizen 9.0 / Chromium M120。以此作为开发基线，但实施第一步仍读取本机实际固件与引擎版本；当前官方型号组表没有直接列出 U8200F，不能仅凭相邻 U8000F 行断言具体硬件组。
- Tizen Web 应用可使用 HTML/CSS/JavaScript，配置 config.xml，签名打包为 WGT。[应用配置](https://developer.samsung.com/smarttv/develop/guides/fundamentals/configuring-tv-applications.html)规定网络访问和平台权限；[证书手册](https://developer.samsung.com/smarttv/develop/tools/additional-tools/vscode/creating-certificates.html)要求有效签名、三星开发者账号、目标设备 DUID。
- [AVPlay](https://developer.samsung.com/smarttv/develop/guides/multimedia/media-playback/using-avplay.html)支持播放状态、跳转、播放速度、流媒体和 DRM 集成。[2025 视频规格](https://developer.samsung.com/smarttv/develop/specifications/media-specifications/2025-tv-video-specifications.html)列出硬件与播放路径限制，尤其 H.264 的 MSE 路径仅到 FHD。电视面板为 4K 不代表任意 Web 播放路径能播任意 4K 流。
- [遥控器手册](https://developer.samsung.com/smarttv/develop/guides/user-interaction/remote-control.html)提供方向、确认、返回和媒体键；[Keyboard/IME](https://developer.samsung.com/smarttv/develop/guides/user-interaction/keyboardime.html)提供文字输入。产品必须设计电视焦点导航，不能直接沿用平板触摸布局。

## 可复用项目与限制

[titlog/bilibili-tizen](https://github.com/titlog/bilibili-tizen)采用 MIT 许可，本次审阅固定提交为 `76003faf3ae1a647a92c532b968e4896427530cb`（2026-10-02）。源码含推荐、热门、排行榜、搜索、动态、稍后再看、历史、UP 投稿、视频详情、多分 P、播放和进度回传；播放器含 Shaka/MSE 与 AVPlay 路径，以及速度选项。许可证允许修改分发，需保留版权与许可说明，附带依赖也需检查许可。

作者报告在 CU7090、Tizen 9 / Chromium 120 上测过，未提供 UN58U8200FFXZC 的测试证据。本次查看的应用代码未发现完整的弹幕、评论、收藏操作、点赞投币、番剧或直播功能模块；字幕也不能按已交付功能计算。

需要先解决的事项：

1. [登录路径文档](https://github.com/titlog/bilibili-tizen/blob/master/docs/登录路径.md)明确默认使用官方电视客户端的 appkey 签名，并有网页扫码路径。前者涉及官方身份复用，不能因为密钥在网上公开就视为获得使用授权；网页路径在作者设备上有多账号和进度回传限制，必须本机复测。
2. [平台实测记录](https://github.com/titlog/bilibili-tizen/blob/master/docs/平台坑.md)报告 Cookie 请求头限制、DASH 清单传递、CDN 403 和接口风控。这些是作者设备/网络/时间点的报告，应作为实验线索，不能当所有三星电视的永久规则。
3. accounts.js 将账号会话写入 localStorage。它不是加密保险箱。扩展前需检查凭据保存、退出、失效和多账号隔离；不能把完整令牌写到日志。
4. config.xml 存在通配网络访问；源码另有更新能力探测与局域网诊断上报工装。自己的发行构建应核实调用路径，删掉不需要的实验探测，按需列出域名，诊断默认关闭并脱敏。
5. 部分源码注释与后续平台文档存在不同阶段的结论。设计依据应取可重现的本机结果，避免直接照搬旧注释。

[Bilibili 开放平台](https://open.bilibili.com/doc)公开介绍账号授权、账号绑定和稿件发布/删除/查询等能力。本次没有找到对普通第三方承诺开放完整推荐、所有视频播放、会员权益、弹幕和互动的一套公开授权接口。公开文档未找到不等于私人合作接口不存在；若要长期公开发行，应先确认合作授权与可用接口范围。

## 推荐架构

以“电视独立运行，必要时接一个自用局域网服务”为策略。

电视端拆成五个模块：电视界面与焦点导航、Bilibili 接口适配、账号状态、播放器适配、字幕/弹幕时间轴。接口适配统一返回可区分的网络错误、登录失效、权限不足、地域限制和内容删除；不要把所有失败展示成“播放器错误”。

播放器先保留并验证现有 Shaka/MSE 的 DASH 主路径，用 AVPlay 处理可支持的直接流或 HTTP MPD。Bilibili 分离音视频需要构建清单并正确处理初始化段、索引与 Range 请求。统一 pause/seek/rate/quality/events 接口，隔离业务界面和播放路径。

纯电视直连若能满足扫码登录和 1080P，就先不增加常驻服务器。若本机的 Cookie、接口请求头、授权流程或 MPD 投递确实受限，再引入一个自用服务：管理已授权会话、适配接口、提供 HTTP MPD；视频分片尽量仍由电视直连 CDN，避免默认转码或全量中转。代理只能解决客户端请求与资源交付问题，不能保证解决 Bilibili 风控、地域限制或内容授权。

局域网服务若必要：先确认一个长期在线的主机；配对访问、凭据服务端保护、退出删除、请求限流、允许的上游域名与脱敏日志。无需在本次研究中更改既有主机服务。

界面使用大字号、清晰焦点、视频网格和侧栏；返回时恢复原卡片。播放中方向键控制进度与面板，确认控制播放，长按返回遵守平台退出行为。弹幕在 UI 层做节流和对象复用；字幕与弹幕不能挡住遥控器控制层。

## 实施阶段与通过条件

以下是一个熟悉 Web 与视频的开发者的粗估，接口问题和授权等待不计在可控开发工时内。

1. **可行性验证，2–4 个工作日。** 读取本机固件/编解码能力；按官方证书流程安装最小 WGT；审查现有项目的鉴权和网络行为；测试游客浏览、网页扫码、登录后接口、退出；播放至少 10 个代表性普通视频，覆盖短/长视频、多 P、720P/1080P、H.264/HEVC。通过条件：用户认可的登录路线能用，1080P 可稳定播放、暂停与跳转，身份正确。若失败，先验证局域网服务是否能解决，再决定是否继续大规模界面开发。
2. **观看核心，1–2 周。** 复用经审查的平台和播放代码；实现首页/搜索/详情/账号/播放五个入口、中文输入、多 P、本地续播、缓存与重试。交付签名 WGT、源码、安装和回退说明。通过条件：全流程仅用遥控器完成，重启可恢复进度，视频失败可重试或返回，退出不继续播放。
3. **平板常用功能，2–3 周。** 加入字幕、弹幕、评论阅读；验证动态、历史、收藏、稍后再看，具备可用接口者交付。先做阅读，再加用户主动触发的互动写入。通过条件：时间轴同步、拖动后恢复、弹幕高密度不影响操作；写入结果明确且不重复；失效会话引导重新扫码。
4. **本机稳定与维护，1–2 周。** 采用约 30 个普通视频的验收清单；持续播放两小时、连续切换视频、断网恢复、休眠/唤醒、断电后登录状态、包更新与回退。目标如首帧中位数 ≤5 秒仅作验收目标，受加拿大网络与 CDN 影响，需要记录条件；不算既有实测承诺。交付已知限制、版本锁定、诊断方式和升级步骤。

按上述完整范围约 4–8 周。仅核心观看版可更早交付。从零重写会增加焦点导航、证书、解码与 CDN 排查成本，不建议作为第一步。公开商业发行另外涉及授权、商店审核、多机型与地区测试，不能纳入这个个人自用估算。

## 发布与维护建议

个人自用先采用签名 WGT 侧载，使用官方 SDK/证书工具链，并保留作者证书、应用 ID、可恢复的上一版包。首次设置需要三星账号与设备证书，登录步骤由用户完成。

不承诺一定能上架三星商店。官方 [TV Seller Office](https://developer.samsung.com/tv-seller-office)有认证流程；[合作卖家规则](https://developer.samsung.com/tv-seller-office/guides/membership/becoming-partner.html)也涉及美国以外地区发布等条件。开源许可证允许用代码，不代表获得 Bilibili 品牌、内容和接口授权。

最终建议：先投入几天完成这台电视的技术验证；成功后扩展已存在的开源客户端，先交付 1080P 的日常观看体验。不要把完整平板功能、官方投屏与会员 4K 同时当作第一版承诺。
