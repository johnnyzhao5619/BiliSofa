# Bilibili 三星电视端：基本功能版实施方案 v2

> 历史资料：评论/回复发布、编辑/删除及点播/直播弹幕发送已由用户于2026-10-14移出范围，现仅查看。当前合同见[PRD](../../PRD.md)和[ADR-003](../../adr/003-read-only-comments-danmaku.md)，下文旧写入条目不再是实施要求。

> 用户已确认所有基本与扩展功能，加官方 App 投屏，一次发布。当前执行依据为 [全功能单次发布实施计划](bilibili-tizen-single-release-implementation-plan-2026-10-14.md)，本文保留此前调研过程。

日期：2026-10-14。目标设备：UN58U8200FFXZC。本文替代 v1 的功能分期与架构决策，平台规格和证书依据见此前调研报告。

## 产品目标

开发安装在三星电视上的 Tizen 应用，以平板端常用功能作为功能覆盖参考，界面与操作完全围绕电视、沙发观看距离和遥控器设计。

默认范围是中国大陆版 bilibili.com、个人家庭使用、中文界面、先适配这台电视。平板和手机只用于扫码登录或可选文字输入，不作为运行应用的必要终端。“本地续播”不能代替“B站账号历史同步”；“游客热门”不能代替“个性化推荐”；“收藏夹浏览”不能代替“收藏操作”。

技术验证包只用于发现问题。基本功能版必须覆盖浏览、账号、个人内容、播放、弹幕字幕、阅读和基础互动；不能仅因一个视频能播放就宣告目标完成。某项接口验证失败时，应记录为未实现并评估替代架构，范围变化需明确说明。

## 新增调研结果

1. [三星输入规范](https://developer.samsung.com/smarttv/design/input-methods.html)要求页面可用方向和确认键操作，栏目与内容切换要恢复焦点。[UX 清单](https://developer.samsung.com/smarttv/design/ux-checklist.html)要求可辨认的唯一焦点、屏幕播放控制、进度和错误反馈。实施应以这些行为为验收依据。
2. [三星生命周期手册](https://developer.samsung.com/smarttv/develop/guides/fundamentals/multitasking.html)要求处理隐藏、恢复、网络变化、会话与内容地址失效。恢复应用不等于继续使用此前缓存的流地址。
3. [社区互动接口记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/video/action.md)描述了点赞、收藏等操作的账号会话与 CSRF 依赖；[评论记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/comment/list.md)涉及 WBI；[字幕记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/video/player.md)指出部分字幕元数据依赖登录；[弹幕记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/danmaku/danmaku_proto.md)描述分段 protobuf 数据及匿名读取限制。以上均为社区整理，并非 Bilibili 官方第三方接口承诺；当前有效性需逐项实测。
4. [bili-webos](https://github.com/asdf17128/bili-webos)具备更接近本目标的功能覆盖。本次查看其源码提交 `e38ed9a83f12d9561a2ecf129c30af615dfc1ee1`（2026-10-11），确认有字幕纯解析函数、弹幕层、个人内容页面与基础互动函数。其 API 客户端调用 `luna://com.biliwebos.app.service/`；这项 webOS 服务依赖不能直接移到三星 Web 应用。其 4K、投屏与旧 LG 机型结果也不能用作三星验证结果。
5. 三星原生参考仍用 [bilibili-tizen](https://github.com/titlog/bilibili-tizen)，审阅版本 `76003faf3ae1a647a92c532b968e4896427530cb`。保留其平台、安装、生命周期与播放器经验，补齐缺少的个人内容和覆盖层。其默认官方 TV appkey 鉴权路线应单独评估，不能据公开源码假设获得官方授权。

本次没有部署应用、使用用户账号调用接口或运行上述项目。源码证据、作者设备报告和本机验收结果分别记录。

## 基本功能版合同

“必做”指交付目标，不是未经验证的可用性承诺。

| ID | 功能组 | 基本功能版交付目标 | 电视操作与通过条件 |
| --- | --- | --- | --- |
| F01 | 账号 | 扫码登录、账号信息、退出、失效提示；先单账号 | 二维码过期可刷新；扫码成功后服务器身份与页面一致；退出后个人页面不再展示原账号数据 |
| F02 | 首页 | 推荐、热门、排行榜、基础分区 | 卡片网格、分页加载、显式刷新；个性化推荐与游客热门分别标识 |
| F03 | 搜索 | 中文输入、热搜/联想、搜索历史、视频与 UP 搜索 | IME 返回焦点正确；结果为空与网络失败可区分 |
| F04 | 关注与动态 | 关注 UP 的视频动态、UP 主页和投稿 | 先覆盖视频动态；图文动态可阅读文字与图片，复杂互动卡后续扩展 |
| F05 | 我的内容 | B站历史、收藏夹列表及视频、稍后再看 | 分页不漏项，失效视频明确提示，列表退出播放后回原卡片 |
| F06 | 播放 | 720P/1080P、画质选择、暂停、跳转、分 P/合集、连播、倍速 | 画质依据账号和源返回；1.25/1.5/2 倍须验证声音与画面；不支持的组合不能展示为可选能力 |
| F07 | 进度 | 本地断点与账号历史同步 | 同账号手机→电视、电视→手机分别验证；同步失败时本地进度仍保存，并显示实际同步状态 |
| F08 | 弹幕 | 普通滚动、顶部/底部、开关、字号、透明度、密度和显示区域 | 跳转清除旧弹幕，暂停冻结，倍速同步，关闭不影响视频；高级代码/BAS 不作为首版必做 |
| F09 | 字幕 | 可用字幕轨道、语言选择、字号、开关、偏移 | 只播放源实际提供的字幕；“无字幕”与“加载失败”分开；不默认进行第三方翻译 |
| F10 | 评论 | 热门/最新评论、楼中楼回复阅读 | 播放器侧面板阅读，不抢播放器焦点；文本不能作为 HTML 或代码执行 |
| F11 | 基础互动 | 点赞/取消、收藏到指定文件夹/取消、稍后再看增删、关注/取消 | 入口在详情和播放面板；提交期间防重复，成功后回读实际状态，失败不伪造成功 |
| F12 | 设置与恢复 | 画质/倍速偏好、弹幕/字幕偏好、连播开关、缓存/账号管理、脱敏诊断 | 断网、隐藏/唤醒、会话过期均有明确恢复入口；设备音量与系统退出键正常 |

第一轮扩展：投币、发评论、回复、发普通弹幕、多账号切换。投币应独立显示数量与确认，不能绑定在长按播放等易误触操作；请求结果不明时先查询状态，不能自动重发。

内容扩展：番剧/追番、直播/直播弹幕及 4K/HDR。它们需要独立的内容、播放与账号权益验收。正式声明支持某项后，才能把它计入交付范围。投稿、购买会员、商城、私信、离线缓存、官方手机投屏不列入本次基本版。

## 电视交互方案

- 主导航：推荐、热门/分区、搜索、关注、我的、设置。我的包含历史、收藏、稍后再看。UP 主页、视频详情与播放器通过返回栈连接。
- 首页默认聚焦“继续观看”中的可用卡片；没有记录时聚焦首张视频。网格以 4 列作为初始设计，允许调整字号与密度，最终以 58 英寸实际观看距离验证。
- 视频详情提供播放、选 P、UP 主页、点赞、收藏和稍后再看；动作菜单有显式入口，不依赖数字键、彩色键或长按。长按可以是辅助快捷方式。
- 播放器控件隐藏时，左右进入跳转预览，确认提交，返回取消；上下呼出控制或选集/信息面板。控件已打开时方向键移动焦点，不与快进动作冲突。
- 返回行为：输入法/弹层→播放控制→播放器返回来源页→页面逐层返回；主页和系统 Exit 按三星规范处理。恢复焦点包括卡片 ID、分页位置与滚动位置。
- 弹幕与字幕按播放时间绘制；播放控制最上层；字幕保留安全区域，弹幕可选择避让。先加载视频，辅助数据随后加载，避免抢占首帧资源。
- 评论和账号功能未登录时给出扫码入口；页面空态不能混用“尚未登录”“没有内容”“请求失败”。

## 架构与复用决策

电视应用仍打包为 Tizen WGT。首个实现基于既有 Tizen 项目受控扩展，先抽出接口和播放器适配层；不要同时更换渲染框架和播放链路。若要迁移 React/TypeScript，应在已测通过的功能基线上另行排期。

| 模块 | 责任 | 复用来源与约束 |
| --- | --- | --- |
| TvShell / Navigation | 遥控器、焦点、返回栈、IME、生命周期 | 三星规范与 Tizen 项目；页面位置按内容 ID 恢复 |
| BiliClient / Transport | API、签名、分页、错误转换、超时取消 | Tizen 接入经验和社区文档；同时支持 DirectTransport / GatewayTransport |
| SessionManager | 扫码、账号身份、失效、退出、会话保存 | 默认用户主动扫码；不把账号密码嵌入应用，不默认为账号增加官方身份 |
| PlayerAdapter | MSE/Shaka、AVPlay、质量能力、事件、恢复 | 保留已审查的 Tizen 路径；替换视频时防止旧回调控制新会话 |
| ContentStore / WriteCoordinator | 视频与列表状态、个人数据、写操作 | 服务器结果决定已赞/已收藏；请求超时视为结果未知而非失败后自动重试 |
| OverlayTimeline | 字幕、弹幕、评论面板 | 参考 webOS 的纯解析和调度代码，重新连接 Tizen 播放时钟与 UI；保留许可 |

**架构通过标准调整：** 纯电视直连必须通过 F01、F05、F07、F11 的关键读写实验，再决定无后端方案成立。只证明扫码或 1080P 播放不够。

若直连无法满足个人功能，优先验证局域网服务：接管扫码回调和 Cookie/CSRF 会话，提供语义明确的业务接口与必要的 HTTP MPD。电视只保存配对凭据和显示状态，媒体尽量直接从 CDN 播放。服务使用已授权会话，不提供任意 URL 代理、不解决内容解锁，也不保证避开平台风控。

局域网服务部署在用户选定的常开主机，配对、访问控制、会话保护、日志脱敏与退出清理需同时完成。若没有常开主机，先验证纯电视路线；不能把缺失的账号功能悄悄移除后仍称完整基本版。正式采用带服务方案前应明确其常开要求与会话保存位置。

以上按一名熟悉 Web 和视频的开发者粗估为 6–9 周，授权等待、重大接口失效、跨多机型适配另计。约两周可能产生可浏览和播放的试用包，但它不是完整基本版。实施范围较 v1 更明确包含个人功能、互动与电视操作验收，估算相应调整。

G0 若发现某个关键接口不可用：先确认会话、权限、签名、网络和源端状态，再验证另一种 transport。确实无可用路径时给出未完成项及范围选择；不开始大范围界面堆砌，也不将降级版冒充原定交付。

## 最终验收

验证分三层登记：源码/解析与状态验证、接口实际读写验证、目标电视操作和媒体验证。桌面浏览器或模拟器通过不能替代 UN58U8200FFXZC 的硬解、遥控器、字幕层和休眠验收。

- 内容样本至少覆盖约 30 个普通视频：短/长、多 P、合集、带/不带字幕、高密度弹幕、H.264/HEVC、不同清晰度；失败和受限内容也验证提示行为。
- 账号路径包括扫码超时、取消、登录失效、退出、应用重启；历史同步在同一账号的手机/网页端回读；收藏和稍后再看在官方客户端对照。
- 播放包括两小时持续观看、快速切换、跨缓冲区跳转、切换质量/倍速、断网重试、Home 隐藏、休眠与恢复。恢复返回来源页并提供“继续播放”，避免未经明确动作自动出声。
- 性能记录首帧各阶段、焦点反馈延迟、卡顿、内存趋势。可先将首帧中位数 ≤5 秒、焦点反馈 ≤150ms 设为工程目标，G0 后按家庭网络修订；这不是现有实测结果。
- 发行包去掉实验探测与不必要的远程执行，诊断默认关闭；账号令牌、Cookie、完整带令牌 URL 不进入日志；证书私钥不进入仓库；包更新保留作者签名和应用 ID，提供上一版回退包。

## 建议

保留“像平板一样有推荐、账号、关注、收藏、历史、弹幕和基础互动”的功能目标，同时将导航、播放面板和阅读方式设计为电视体验。先做覆盖账号读写的验证，而不是只测播放器。借用 Tizen 项目的平台能力与其他电视客户端的独立功能模块，逐项建立本机证据。

个人自用侧载与公开商店发行分别评估。社区接口记录和 MIT 代码许可不会自动提供 Bilibili 接口、内容或商标授权；若计划公开发行，应先确认接口合作范围与三星上架条件。
