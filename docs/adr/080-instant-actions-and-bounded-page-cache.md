# ADR-080：单击可逆互动、倍速与有界回看缓存

2026-10-22；F06/F11/F12、U4。用户明确要求三个播放快捷动作无需二次确认，统一操作/业务逻辑。本决定覆盖ADR-062/078/079中仅对点赞、关注UP、稍后再看的预览要求；收藏夹精确目标确认、F14暂停、旧unknown及单账号保护保持。

## 行为和权限

- 播放页先只读加载实际状态，三个按钮统一以一次显式点击授权当前内容的可逆切换；运行时仍验证身份/目标、先持久记录、最多一次POST并回查。已点赞/关注/加入时显示已设置状态，点击为取消；视频继续、焦点留原控件。收藏夹保留独立选夹及预览，避免重复的三条动作路径。
- 同一时刻串行；切源/Home取消并等待旧句柄关闭。旧值与新读不一致时仅更新状态，不替用户反向提交。读取失败/能力未确认可独立核对，不把未知当未设置，不因余额或收藏夹失败锁死其他能力。
- unknown跨重开保留；读取前先识别持久pending/unknown族，即使本次GET已能结算，下一次该动作点击也只回查。不可把读恢复变为自动重发。代理不会执行真实账号POST；本次授权是用户在应用中点击的产品合同，不是无人值守提交权限。

## 关注和点赞调查

0.37.0用户确认点赞`API -403`且回查未点赞、关注按钮灰色、稍后再看成功；倍速及Back/Home通过。官方网页静态代码读取`GET /x/relation`的`data.attribute`，未依赖`data.mid`。本项目旧解析器要求mid，现允许缺省但若返回仍须匹配固定请求的UP；异常attribute继续拒绝。该兼容错误已修正，但没有本次电视原响应，不能宣称它已证明就是灰色按钮的唯一根因。

点赞路由/aid/like/CSRF已与官方页面核对；-403仅能确认服务端拒绝和未应用，尚不能区分账号权限/额外校验原因。未伪造网页播放器风控字段、客户端身份或签名，未把补错误码当根因修复。R03实际点赞仍OPEN。详见[本次来源](../research/2026-10-22-interaction-recheck.md)。

## 遥控与缓存

倍速为播放中的右侧单列单选菜单，打开聚焦当前档位，勾选表示实际接受值；上下移动，确认立即生效并回原按钮，Back不修改。当前只列真实可用1×/2×，提示更多倍速暂不可用；小数倍速后端仍是F06待办，不能称全部倍速已实现。

连续网格使用页面owner内LRU：最多8批/32张卡与封面资源、DOM最多3批/12卡，5分钟过期。Up/再次向下命中直接复用节点/封面与焦点，不发列表请求；过期/被淘汰才读。刷新、查询/类型/私有来源更换和owner关闭释放缓存，账号会话由原owner代次隔离，不持久保存私人列表。缓存回看同步页面记忆。不是全部加载，也不新增外部服务。

0.38.0使用独立`--product-instant`/输出/私有签名部署指针，0.28–0.37冻结。桌面只用合成账号/AVPlay，真实写入失败和最终设备/性能验收分别保持。仅安排本轮受影响的三项操作、倍速和缓存集中验证，不重测旧A–E。
