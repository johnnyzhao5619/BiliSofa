# ADR-056：直播CDN启动回退与分阶段错误

状态：2026-10-20，0.21.4已装机但实播仍FAIL：`live.network.source.manifest_h0_c28_n2`。用户已批准直播延期至后续版本，后续执行以[ADR-057](057-live-release-deferral.md)为准。本决策保留策略/失败证据，不恢复固定型号/分辨率门禁。

## 证据与缺口

用户报告0.21.3直播只有控制条、反复准备后`live.network.source`；没有足够信息区分API、CDN清单、首分片和本地监听。另确认普通点播标称4K（读数3108×2160、25.253fps）可播放，下一条缺4K时自动选1080P高码率（1920×1080、24fps）播放正常；保留原读数，不改写为3840。它是用户声画/界面观察，不是独立decoder/HDR认证。

匿名读取[官方直播首页](https://live.bilibili.com/)及一间新推荐源：API HTTP200/API0，实际720P AVC，声明两个CDN。开发机两节点的DNS/TCP/TLS正常，HTTPS清单无HTTP响应而超时；规范查询分隔符、添加Referer、HTTP/2及通用浏览器UA对照未解除。仅证明该主机/该公开样本的HTTP阶段阻塞，**不能唯一归因用户电视**，不把备用节点切换描述为已解决真实直播。

同时确认实现缺口：只取`url_info[0]`；原`base_url`以`?`结尾、`extra`无前缀时会多加`&`；泛化network错误丢失失败层次。原始响应/签名地址仅仓库外由`w04-live-214-latest.json`定位，脱敏摘要在ignored日志；不打印URL、地址或个人资料。

## 决策

- 修正查询拼接：结尾已有`?`或`&`时不再加分隔符；保留签名参数原顺序/编码，不重排或自行修改CDN参数。旧匿名探针和产品共用严格URL函数。
- Worker私有保存API实际提供、完整校验后的去重候选，最多3个。**只在起播前**遇到清单/首分片网络或超时失败时，取得旧引擎真实`LIVE:closed`后尝试下一节点；未知关闭、权限/TLS、无效格式或本地监听失败不借此重试。每次节点的清单与首分片独立校验，Range/TS/TLS/目的地限制保持。
- 同一启动总预算28秒。节点耗尽后明确终止，公共`exhausted`标记阻止播放器再次重复整组API/相同节点；已起播后的有限恢复仍按ADR-053/055。没有备用节点就不能伪造地址。
- 公开状态只含固定阶段`api/manifest/probe/listener/segment`、节点序号≤3、HTTP0..599、cURL-1..999和耗尽布尔值。-1/HTTP0表示未取得完成值/响应，不伪称cURL28。UI显示阶段进展，最终错误附`.manifest_h0_c28_n2`等后缀；登录包装同样转交有界元数据，不携带凭据、签名源或原始错误。
- 本地并行开发机不是运行依赖，不增加常开服务或新的网络权限；原生模块字节保持不变。

## 验证

覆盖查询分隔符/参数字节、备用去重/目标拒绝、首节点失败后同Worker实际关闭再起、全部节点失败只读一次API、TLS不重试、Back取消与有界状态防泄漏（含登录包装）。生产C的11项HOST检查另验证同一运行时关闭后重启匿名引擎；其余旧原生/SDK证据按字节复用。

浏览器native/decoder仍为合成替身。用户补回终态确认第2个CDN清单无HTTP响应/cURL28，策略未解除真实故障；不推断具体网络或服务端根因。直播实播/消息/恢复现按ADR-057延期，不再请求复测。E独立运行、F17真实写回及HDR等缺证另见W04收尾表。
