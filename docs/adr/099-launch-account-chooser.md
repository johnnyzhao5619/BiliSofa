# ADR-099：启动时选择账号（“谁在观看？”）

2026-10-23；F01/F13、R06/R15、U5。用户要求参考YouTube电视客户端：启动时就让用户选择是否登录、用哪个账号；之后支持多账号时可记录更多账号。仅在`--product-profiles`（0.50.0）构建生效。状态：**0.50.0已签名并升级安装/启动；P1 USER PASS、P2暂缓（待多账号）、P4部分通过（见文末）；0.50.1（界面统一、失败摘要）已签名并升级安装/启动，P1′ USER PASS；P4′失败摘要为network，见[ADR-100](100-bounded-playback-reconnect.md)**（[证据](../design/evidence/2026-10-23-profiles-fix/README.md)）（[证据](../design/evidence/2026-10-23-profiles/README.md)）。

## 现状

应用每次启动都是游客身份，不恢复上次账号。已保存的账号需要进入“账号”页按“使用 …”，每次启动都要重复。

## 决定（参考电视端账号选择的通行做法）

- **冷启动且电视上有已保存账号**：
  - 全屏显示“谁在观看？”：每个已保存账号一张卡（名称首字、名称、提示），另有“游客浏览”和“添加账号”。
  - 焦点在上次使用的账号上。按卡片走现有的账号身份核对，成功后进入首页并记住这次选择。
  - 选择前不读取任何私人内容。
- **冷启动且没有已保存账号**：
  - 显示一次欢迎页：“扫码登录”或“先以游客浏览”。
  - 选游客后不再显示，直到电视上有了已保存账号。
- Back等于游客浏览。从Home返回（后台恢复）不再询问，沿用当前身份。
- 登录已失效的账号在卡片上标“需要重新扫码”。选择后交给现有的会话恢复流程（ADR-082）：进入账号页的重新扫码，成功后回到原页面。
- 本机只保存上次选择的账号id（`bilisofa.last-profile.v1`）和“已选游客”标记（`bilisofa.launch-guest.v1`），不保存任何凭据。移除账号时一并清除对应的id。
- 多账号：选择页按已保存账号逐一列卡，不限于一个。真实双账号功能与验收仍按ADR-069不在本版，单账号安全模型不变。
- 不做：自动登录上次账号（共用电视的隐私问题，与“谁在观看”的目的相反）；PIN或儿童模式；从网络取头像（启动时不读私人内容）。

## 证据

合成UI`tests/product-profiles-ui/profiles.spec.ts` 5条：
- 多账号列卡且首个获焦；
- 选择后关闭并记住，重启后焦点在上次账号，本地不含凭据；
- Back保持游客且不读私人内容；
- 无账号时欢迎页只出现一次；
- 失效账号标注后交给重新扫码恢复。

汇总见[证据](../design/evidence/2026-10-23-profiles/README.md)。

## 0.50.0真机结果与0.50.1（2026-10-23）

- **P1 USER PASS**（冷启动出现选择页，焦点在上次账号；选择与Back均正常）。**P3 USER PASS**（热门番剧筛选与保存）。
- **P2 暂缓**：按用户决定，等后续支持多账号后再测“添加账号”与失效账号的重新扫码。不记PASS，也不阻塞本版。
- **P4 部分通过**：
  - 部分国创视频提示“网络连接中断，播放未完成”；标“限免”和“会员”的凡人修仙传可以播放（用户为已登录会员）。
  - 本机匿名核对：排行前十的国创，首集的主地址多为海外节点`upos-sz-mirrorcosov.bilivideo.com`，备用为`upos-hz-mirrorakam.akamaized.net`，现有地址规则可接受主地址；另有个别番剧返回-10403（地区不可看），该码映射为“无权限”，不是“网络中断”。
  - 所以“网络中断”来自播放源读取或分段传输中的其他失败，本机无法复现登录后的真实响应。不凭推测放宽原生地址白名单。
  - 0.50.1在“设置 → 帮助与诊断”顶部显示“最近一次播放失败：阶段 · 原因 · 代码”（固定词汇，无地址）。用户复现后报告这一行，再定修法。
- **P1界面统一（0.50.1）**：
  - 原选择页被通用弹窗样式套成带边框的对话框，背后是变暗的首页，卡片溢出边框。
  - 改为与产品页一致的整页：应用背景、左上角品牌“B”、与页面相同的眉题与48px标题；卡片与内容卡同色同圆角，获焦为粉色描边加轻微放大与阴影（减少动画时不放大）；账号用粉色首字头像，游客与添加账号用与侧栏一致的线性图标。
- **过程问题与恢复**：为截图对比曾用0.50.0参数重建，覆盖了0.50.0暂存目录`dist/product-profiles-app`。已从冻结的0.50.0未签名包（`3db7d810…a664a`）取回文件，并从签名回执的源码归档取回`ui-manifest.json`（哈希与回执一致）；还原后与签名前快照一致。0.50.0签名包与未签名包未受影响。之后的修改只用新变体`--product-profiles-fix`（0.50.1）构建。
