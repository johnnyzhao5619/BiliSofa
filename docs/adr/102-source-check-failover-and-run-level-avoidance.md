# ADR-102：来源检查主备切换、尊重B站地址顺序、本次运行内避开失败节点

2026-10-23；F06/F17、R13、U5。接0.50.3真机P4‴：伍六七之玄武国篇第1集正常播放，第2、3集（会员集）仍显示网络连接中断，自动重连后失败。诊断为`phase: source`、`reason: network`，失败前没有任何开始播放的记录。仅在`--product-source-failover`（0.50.4）构建生效。状态：**0.50.4已签名并升级安装/启动（平台确认，不清数据）；P4⁗ USER PASS**（[证据](../design/evidence/2026-10-23-source-failover/README.md)）。

## 原因判断

- 按代码，`source · network`有三种来源：
  - 读取播放信息的请求（登录状态、番剧信息、播放地址）失败；
  - 开播前的来源检查失败，即读取视频、音频文件前512字节以确认文件大小；
  - 播放桥接在播放器之外被停止。
  - 在`MediaSession`里，桥接因任何原因结束都会记为`source`。
- 0.50.3只给播放桥接加了主备切换。来源检查仍然只读主地址，失败就直接结束，所以“免费集能播、会员集不行”符合这个缺口。
- 无法确认的部分：
  - 匿名请求第2、3集只拿到试看片段，没有完整文件，也不使用账号读取；
  - 第1集对照显示，主节点读文件开头都很快，读到中间大多超时。会员文件实际分到哪个节点、开头能否读到，只有真机诊断能说明。
  - 所以本版同时细化诊断。

## 决定

- **来源检查主备切换**：
  - 每条轨道先查第一条线路；遇到网络错误或超时，改查该轨道的备用线路，每条轨道最多换一次；
  - 检查通过的线路成为播放桥接的起始线路，另一条作为桥接的备用（0.50.3的桥接切换继续生效）；
  - 两条都失败时保留原错误。
- **原生模块**：新入口`vod-api-failover.c`、`pgc-read-failover.c`，原样包含`vod-api.c`和`pgc-read.c`，只叠加ADR-101的Akamai规则（`vod-cdn-policy.h`）。分别链接到新目录`build/vod-api-failover`、`build/pgc-read-failover`，原模块和冻结目录都不变。
- **尊重B站地址顺序**：
  - 按B站给出的base/backup顺序使用；
  - 只有国内边缘节点（`*.bilivideo.com`中非`upos-`开头的，如`cn-…`）排在B站镜像和Akamai之后。
  - 0.50.3为了配合未改的来源检查，强制以bilivideo地址为主；本版取消这一限制。
- **本次运行内避开失败节点**：
  - 来源检查或桥接切换中失败过的节点类别（B站镜像、B站Akamai、国内边缘节点），在本次运行中排到另一条线路之后，只调整顺序，不删除候选；
  - 换集、重开番剧页、重连都从可用线路开始；
  - 不持久化，重启应用后清空；
  - 只有固定类别离开媒体Worker，主机名和地址都不离开。
- **细化诊断**：
  - “帮助与诊断”的失败摘要写明失败的步骤：读取播放信息（登录状态、番剧信息、播放地址）、来源检查（视频或音频、主线路或备用线路、节点类别）或播放桥接；
  - 同时给出上游HTTP/cURL代码或“上游超时”，以及“已切换备用线路 N 次”；
  - 均为固定词和整数；每次读取播放源时重置步骤，切换次数和避开的类别按本次运行累计。
- 0.50.2的有界重连与0.50.3的桥接切换都保留。

## 不做

- 不改写主机，不加入其他第三方CDN、mcdn或PCDN节点。
- 不用账号做诊断读取，不持久化节点信息。

## 证据

- 原生主机测试`tests/native/source-failover.test.py`，37条：
  - 两个新入口跑完原有VOD/PGC读取全部检查（TLS、cookie隔离、重定向、关闭等）；
  - 来源检查只接受Akamai族；
  - 原PGC入口仍拒绝该族。
  - 原`vod-api`与`pgc-read`测试仍通过。
- 单元`tests/unit/vod-source-failover.test.ts`：
  - 地址顺序与边缘节点后移；
  - 检查失败时换线，两条都失败时保留原错误；
  - 避开的类别不再先查；续期保持原主机；
  - 诊断代码只接受固定格式。
- 合成UI`tests/product-source-failover-ui/source.spec.ts`，3条，经真实的来源Worker、桥接Worker和页面：
  - 主线路检查返回504时，两条轨道都从备用开始，切换2次；
  - 再次播放不再先查失败的线路，仍为2次；
  - 两条线路都失败时，诊断写明“来源检查（视频·备用线路·B站Akamai） · 上游 HTTP 504 / cURL 0”。
  - 对冻结0.50.3三条都失败；去掉运行内避开的变异版本使第2条失败（切换4次）。

## 真机结果（2026-10-23）

P4⁗ USER PASS：伍六七之玄武国篇第1–3集均可播放。播放源问题（P4，ADR-099文末至本ADR）就此收口；其他片源与网络条件仍随R13最终恢复矩阵验证。
