# ADR-114：P2a界面与布局——首屏多看一排、“小电视”焦点框、详情两栏、骨架加载与样式收拢

2026-10-26；F01/F02/F05/F06、R01、视觉与布局。接2026-10-25 review第七章与ADR-113。状态：**用户已确认全部决定（2026-10-26）；0.61.0已安装，实看通过；第3项（模糊背景）实测拖慢方向键，按本决定在0.61.1关闭；0.61.1已安装，首页方向键回到0.60.0水平**。改动方案见[P2a方案](../archive/2026-10-26-plans/2026-10-26-p2a-layout-plan.md)。

## 背景

用合成UI在1920×1080下截取了现在的主要界面（[基线截图](../design/evidence/2026-10-26-ui-baseline/)，合成数据没有封面，显示的是占位）。逐屏看到的问题：

| 界面 | 现状 | 截图 |
| --- | --- | --- |
| 首页 | 标语“BiliSofa · 坐下来，看点喜欢的”加大标题“今天，想看什么？”占了约200 px，首屏只放得下一排货架多一点 | 1-home |
| 首页卡片 | 标题一行，与“UP · 播放数”之间留了很大空白；标题长时被截成一行 | 1-home |
| 首页失败货架 | “重试”“查看更多”做成两块和卡片一样大的方块，比内容还显眼 | 1-home |
| 详情页 | 右栏只有标题和一行信息，近一半画面是空的；操作按钮挤在封面下方 | 3-detail |
| 播放器快捷设置条 | 与主行不一致：没有图标，按钮高度、字号不同 | 5-quick |
| 播放器进度条 | 4 px细线，聚焦时也不变粗；时间单独占一行 | 4-player |
| 搜索 | 候选区空着时显示一排排“—”；“更多候选”折成两行 | 7-search |
| 样式文件 | `product-ui.css`约33 KB，同一选择器在多处覆盖（例如`.tv-card:focus`、`#overlays>section.tv-detail`各有两三处定义），改一处常被另一处抵消 | — |

已经做得不错、保持不动的：

- 侧栏获得焦点时展开显示文字；
- 卡片聚焦时放大1.05（减少动画时不放大）；
- 深蓝底配品牌粉只用于焦点与主按钮；
- 播放器底部渐变与主行图标。

## 决定

1. **首页：首屏多看一排，卡片信息紧凑，失败不抢眼，加载有骨架。**
   - 去掉首页的标语与大标题，改为左上一行小字（当前身份），首屏能看到约2.5排货架（下一排露出一截，提示还能往下）。
   - 卡片：标题最多两行；“UP · 播放数”紧贴标题；时长角标不变。
   - 失败的货架：只占一行，左边是原因，右边是“重试”与“查看更多”两个普通按钮。
   - 加载中的货架：显示与真实卡片同尺寸的灰色骨架卡，加载完原位替换，布局不跳。
2. **“小电视”焦点框（本次唯一的特色元素）。**
   - 内容卡片聚焦时：在现有放大1.05与粉色描边之外，描边上方加两根短“天线”，让焦点像一台B站小电视；
   - 只用在内容卡片的焦点上，按钮、菜单与其余界面保持安静；
   - 用纯CSS（伪元素）实现，不加图片；减少动画时不放大，天线照常显示。
3. **背景氛围：用已加载的封面做模糊暗化背景。**
   - 首页：焦点卡片停留约300 ms后，把它已加载的封面放大、模糊、调暗，铺在页面背景上，焦点移走时淡出；
   - 详情页：用这个视频的封面做同样的背景；
   - 不发额外请求，只复用卡片已经加载的封面；没有封面时不显示；
   - 在电视上测连续方向键的响应，若比0.60.1明显变慢，就关掉这一项（模糊在这台电视的GPU上开销未知）。
4. **详情页改两栏。**
   - 左：封面；右：标题（最多两行）、UP与数据一行、简介三行（超出有“简介全文”）、操作按钮一行（主按钮“播放/继续观看”在最前）；
   - 分P或合集一行横排放在两栏下方；
   - 焦点与按键顺序不变：进入时焦点仍在主按钮。
5. **播放器细节。**
   - 快捷设置条的按钮与主行同样式（图标加文字、同高度）；
   - 进度条加粗到8 px，聚焦时12 px；当前时间与总时长放在进度条右端，不再单独占一行。
6. **搜索细节。**
   - 候选区为空时不显示“—”，改为一行提示“按首字母出现候选”；
   - “更多候选”改为“更多”，不再折行。
7. **样式收拢（不改行为）。**
   - 把颜色、字号（页题48、章节36、卡片标题28、辅助22）、间距、圆角、焦点集中为一组变量；
   - 合并同一选择器的重复定义，删除被覆盖、已无作用的规则；
   - 合成UI全部通过，并逐屏对比截图，确认除本ADR列出的变化外，外观不变。

## 实现（0.61.0）

按上述决定实现；以下是落地时定下的细节与偏差，均不改变决定本身。

| 决定 | 实现 |
| --- | --- |
| 1 首页 | 首页标题区改为一个`h1.tv-home-identity`（“BiliSofa · 账号昵称/游客”，22px）；搜索页标题不变。货架卡由387px改为340px宽，才能让首屏放下约2.4排；标题28px最多两行、元信息紧贴。“查看更多”网格仍保留两行标题高度，因为连续网格用第一张卡的高度推算行距。骨架卡5张，不可聚焦；读取状态文字仍在（读屏可读），视觉上隐藏。失败货架用`tv-shelf-failed`类改成一行；重试期间保持一行，成功后才恢复卡片行，避免来回跳动 |
| 2 焦点框 | `.tv-content .tv-card:focus`的`::before/::after`：6×22px粉色短杆，各倾斜28°，落在外轮廓上方；货架行顶部留白加到48px，放下放大后的卡片和天线。图书馆/继续观看卡片不加 |
| 3 背景 | 新模块`apps/tv/src/ui/backdrop.ts`：只接收页面里已有图片的`src`（CoverArt的blob地址），首页焦点停留300 ms后淡入，移到非卡片或无封面的卡片时淡出；详情页用封面图。`BACKDROP_ENABLED`一处关闭。`#pages`加`isolation:isolate`，否则背景层被body底色盖住（html另有底色，body背景不再传到画布）。播放时（`playing-media`）不绘制 |
| 4 详情 | 操作按钮移入右栏（`tv-detail-summary`），数据行与简介插在按钮之前；简介3行，超过90字或3行就给“简介全文”（`needsFullText(text, 3)`）。焦点仍从“播放/继续观看”开始，分P一行仍在两栏下方 |
| 5 播放器 | 快捷设置条五项加图标（新增`quality`/`rate`/`repeat`三个路径，弹幕、字幕沿用），标签更新改用`setLabel`以免冲掉图标；进度条8 px、聚焦12 px；进度条与时间包进`tv-player-track`一行 |
| 6 搜索 | 候选为空时显示一行提示（未输入“按首字母出现候选”、查找中“正在查找候选”、无结果“没有候选”），空位隐藏；“更多”保留读屏名“更多候选”。候选被选中后会隐藏并先失去焦点，所以改为在重绘前记下焦点元素，焦点仍落到“搜索” |
| 7 样式 | 新增变量`--tv-line`、`--tv-fs-page/section/card/aux`、`--tv-radius`、`--tv-focus`；合并`#overlays>section.tv-detail`、`.tv-detail .tv-secondary`、`.tv-search-actions`、关注页副标题的重复定义；`#526078`边框与粉色焦点外轮廓改用变量 |

结果：单元774/774，合成UI 109/109（新增`tests/product-polish-ui/layout.spec.ts`四条），打包负例12/12，`npm run check`通过。截图对比见[P2a截图](../design/evidence/2026-10-26-p2a-layout/README.md)：我的、关注、设置三屏与基线逐像素相同；其余变化都在本ADR范围内。设备观感与第3项的按键响应测量尚未进行。

## 设备验证（0.61.0）

[设备证据](../design/evidence/2026-10-26-p2a-device/README.md)。用户实看首页、焦点框、背景、详情、播放器、搜索6项，全部与描述一致。

首页方向键响应以已安装的0.60.0为基线（0.60.1未安装，且与首页无关）：

- 间隔600 ms时，中位数32→72 ms，每隔一次按键卡0.6–1.5 s，帧数少约三分之一；
- 间隔150 ms时，中位数不变，但偶有约1 s的卡顿。

在同一包上逐项排查：

- 隐藏背景层、去掉`isolation`、去掉天线，都没有改善；
- 禁止背景层给图片设封面地址后，中位数回到31 ms、帧数恢复。

所以开销主要在背景层装载封面，与是否显示无关。按第3项，应把`BACKDROP_ENABLED`设为false，作为新版本签名安装，并从新启动的应用复测；那时再确认剩下那一次约0.5 s的卡顿是否还在。

**0.61.1**：`BACKDROP_ENABLED = false`，`backdrop()`不再添加图层，`show`什么都不做；首页与详情页的调用保留，日后要重开只改这一处常量。背景样式与`#pages{isolation:isolate}`保留（不影响响应，见上面排查）。合成UI的背景测试改为：给聚焦卡片放入已加载封面后，首页与详情页都没有背景层。单元774/774，合成UI 109/109，打包负例12/12。

0.61.1设备复测（新启动的应用，与0.60.0同法）：
- 间隔150 ms：中位数33 ms，p95 49 ms（0.60.0为34/52 ms）；
- 间隔600 ms：中位数30 ms，p95 34 ms（0.60.0为32/37 ms）；
- 没有超过200 ms的按键，也没有超过100 ms的帧；
- 0.61.0排查时剩下的那次约0.5 s卡顿没有再出现。

## 不做

- 侧栏结构与导航项（ADR-113第4项，P1-2b）。
- 文案与死代码清理、按键响应改进（P1-2b）。
- 首页快照持久化、云端播放进度上报（review第七章提到，但不属于界面与布局，另行安排）。
- 自定义字体（`TV_PRODUCT_DESIGN.md`：不从外网加载字体）。
- 自动播放预览与动态大背景（`TV_PRODUCT_DESIGN.md`禁止）。

## 验收与证据

- **截图对比**：用同一脚本（基线目录里的`shots.spec.ts`）在实现后截取同样九屏，与基线并排对比。
- **合成UI**：保留套件全部通过；新增：
  - 骨架卡在加载时出现、完成后替换；
  - 失败货架只占一行；
  - 焦点框伪元素存在且只在卡片焦点上；
  - 背景在没有封面时不出现。
- **设备**：
  - 实际观感（真实封面与文字）；
  - 用Inspector测首页连续方向键的响应时间，与0.60.1对比，用来决定第3项是否保留。

## 风险

- **模糊背景的性能**：Tizen电视GPU能力未知，大图模糊可能拖慢焦点移动。以设备测量为准，必要时关闭第3项。
- **焦点框的取舍**：“天线”是本次唯一的风格冒险；如果实际观感不好，可以只保留放大与描边。
- **样式收拢的回归**：33 KB样式里有补丁式覆盖，合并时可能改变个别页面的外观；以截图对比与合成UI兜底。
