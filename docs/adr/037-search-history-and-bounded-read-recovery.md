# ADR-037：身份隔离搜索历史与有界读取恢复

2026-10-18，W03/F03/F12/F13，媒体取源影响F06。0.7.0 USER报告首次search.http_412、同视频首次ugc.audio_transport_28，第二次各自成功，ZG输入Back通过；不将恢复记作首播稳定通过，也不推定翻页/播放Back已确认。不重复原人工组。

curl官方错误表将28定义为操作超时（https://curl.se/libcurl/c/libcurl-errors.html，2026-10-18核查）；当前Worker将C音轨0–511范围检查的返回码拼为audio_transport_28。仅据此定位阶段/超时，不能确定DNS、连接、TLS或收包哪一步，也没有证据归为codec/权益错误。412原因未定，禁止靠改身份/凭据/UA或自动循环请求来消除。

0.8.0新增显式“重试当前搜索”：保留本次词和失败页，用户动作重新发一个有scope的GET；不再强迫重新输入。历史保存在独立固定键bilisofa.search.v1.<localOwner>，schema1、开关和至多12词、4KiB，词受现有32码点/128bytes合同约束；查询尝试即记入，所以412后仍能找回。去重最近优先，不写外部JSON/URL/凭据/云端，也不进诊断。普通偏好v1不改/不迁移；坏/未来记录不覆盖，失败不阻止搜索。关闭记录仅停止新增，已有词仍保留并明确显示；独立确认清空；移除账号需先确认其普通本地和搜索分区清除，未知保留账号，其他身份和未知写journal保持。

媒体仅对guest-video-play准备前的video/audio范围GET，收到真实GUEST:closed后、rc28且HTTP尚无状态或为206/无正文头部策略拒绝/地址至少75秒有效、尚未重试过时，延迟750ms同阶段同地址重试一次；预算在一次媒体owner内，不随source刷新重置。SOURCE诊断、HTTP/API/412、TLS/范围/解析、详情/playurl、已经开始的bridge/播放都不重试。无关闭事件不重试；Back/Home先使owner失效，延迟任务可取消。固定进度事件和UI提示一次重试（原8条父端进度限额仅增加此额外1条，仍有界），失败保留最终原码，不伪造声画或清理。仅JS/合同装配，不改C/SDK/TLS/CA/目的地/8秒请求上限。

验证包括历史存储隔离/重开/上限/坏数据/确认删除/账号移除，显式搜索重试不重复输入，无自动412重试，音轨28一次恢复/重复失败/非28无重试/等待中取消与不依赖fake-close的native帧。旧原生文件全部保持，效果只按证据层报告。唯一新增USER组为记录一个词（即使HTTP失败也不反复请求）、退出重开历史、关闭记录/确认清空；不要求重复音轨超时、原搜索/播放/三端或W01。
