# ADR-011：投屏轮询连接预算

日期2026-10-16。W01/F06/F20，0.0.48内部候选。0.0.47首源设置握手已取得用户手机时间正常，但约62秒自动退出，70秒连续播放未通过。

原128次累计HTTP连接预算来自发现探针，持续GetTransportInfo/GetPositionInfo轮询也计数，并在耗尽时关闭整个cast/媒体。HOST用旧预算真实重复请求复现停止；新预算跨过旧边界继续RPC，达到新边界仍关闭。单份旧TV报告没有原因位，因此区分源码可复现缺陷与本轮TV精确触发证据。

固定累计预算调整为1024，同步内部RPC ID到1..1024（接入前再核查总数，避免两个空槽在同tick越界）；两并发客户端、单连接5秒、最多24条播放器命令、scope/owner/精确URI、TLS/CA、源检查8秒、发现5分钟、媒体3分钟与字节/窗口预算保持。该容量适配三分钟内常见约2Hz状态/进度短连接轮询且留描述/源设置/准备余量，属于项目预算，不是B站承诺的固定轮询频率。恶意或更快的访问仍可能提前用尽上限。

关闭前区分connections和lease两个固定原因，Worker严格白名单及8项报告保留，不输出地址/原始请求/URI或精确计数。IPC去重进度178→180，SOAP64位/receiver32位不变。原生代码改变须真实Samsung SDK重编译、HOST检查及包完整性检查；桌面/本地不代替电视90秒持续声画与手机时间验收。

HOST旧预算对照在同一测试实现中仅把连接常量设回128，保留新增原因日志/接入检查以隔离预算变量；它不是0.0.47工件逐字节运行，不将其日志冒充旧TV日志。


0.0.48真机后续：已跨过原62秒且连续90秒/手机时间USER PASS，2:57停止的精确报告为media_limit_lease/flow_l0，即现有三分钟媒体预算触发。0.0.49为验证3:42自然结束，将progressive媒体及SOAP接收许可改为五分钟，signed deadline仍提前5秒截断，准备/暂停也计时；不改变1024累计连接/RPC和其他流量/并发/命令预算。常见约2Hz×300秒约600次留有余量，不承诺未知频率下无限接收。监听沿用原逻辑至少至媒体截止+1秒，未投送发现5分钟不变。flow l6为饱和桶（>150秒，含≥180秒），保持格式；不是精确剩余租期。测试须跨原180秒并验证最终截止与短签名截止仍关闭，具体TV自然结束待验收。


0.0.49实机218秒完整声画和手机/TV进度USER PASS，但报告投屏清理unknown；另一个诊断HTTP GET关闭不能替代投屏关闭。0.0.50修正父层310秒看门狗与native最长5分钟发现＋5分钟媒体的不一致，父层改610秒，native租期/签名/所有网络和命令预算、5秒清理ACK不变。旧报告无精确时间/首个错误，尚不能判定它触发本样本。增加固定父层/native/runtime失败分类与失败分支的关闭进度保留，不能用“播完成功”覆盖清理未知，也不能延长ACK或悄悄复用poisoned Worker。
