# ADR-105：登录时用本人会话读取公开列表，请求节奏与可见的风控结果，本机记录与队列的完整详情页

2026-10-23；F02/F04/F07、R05/R15、U5。接0.51.1真机结果。用户确认方案（含“登录时用本人会话只读读取公开分区与UP投稿”）。仅在`--product-up-fix2`（0.51.2）构建生效。状态：**0.51.2已签名并升级安装/启动（平台确认，不清数据）；V1（登录状态）、V2②补、导航与UP主页回归 USER PASS**（[证据](../design/evidence/2026-10-23-up-fix2/README.md)）。

## 0.51.1真机结果

- **V1 FAIL**：分区仍全部无法加载。
- **导航 PASS**。
- **V2②**：稍后再看、云端历史、收藏夹 PASS；“我的”中的“继续观看”“本机播放队列”仍是旧面板。
- **关注页直达卡 PASS**。

## 原因

- **分区**：限时只读核对推翻了ADR-104“只换User-Agent即可”的结论。
  - 本机编译的生产原生代码，带真实Tizen串向B站请求，分区与全站榜都返回-352；
  - 同一时刻用Python、同一个串对照，也返回-352。
  - 可见风控结果取决于状态，即同一网络近期的请求情况；早些时候的“Tizen串可读”只是宽松时段的样本。
  - 推断（未证实）：电视与本机很可能共用同一公网出口；当天大量匿名探测可能抬高了这个出口的风控等级。这条请求本身不带任何cookie，而浏览器与官方客户端都带访客标识，登录后还带本人会话。
  - 电视界面只显示“内容暂时无法加载”，代码藏在`status.title`里，所以真机无法区分是哪一层出了问题。
- **继续观看与本机播放队列**：ADR-104有意为它们保留旧面板（为了队列与删除操作），不符合用户预期。
- **焦点**：“重试”成功、改为加载上一个可用列表时，焦点仍会落到`BODY`。0.51.1只处理了失败的情况；合成UI加严后对冻结0.51.1复现。

## 决定

参照B站官方网页、主流第三方客户端与社区接口文档的做法。

- **登录时用本人会话**：
  - 有活动账号时，分区排行与UP投稿走新的只读通道`public-read`。原生入口`public-read.c`原样包含`vod-api.c`（TLS、两套cookie、本人身份核对、有界关闭），只允许三个操作：0号身份核对、4号单个分区排行（编号取自固定分区表）、5号UP投稿一页（mid|page，均有上限）；
  - 链接到新目录`build/public-read`；Worker为`public-read-worker.js`；
  - 账号只在Worker通道内，页面拿不到；只发GET，没有写入、CDN或playurl路由；
  - 游客仍走匿名catalog通道。
- **请求节奏**（进程内）：
  - 成功的分区或UP投稿结果复用10分钟；
  - 收到风控拒绝（API -352/-412/-509/-799或HTTP 412）后暂停60秒，期间不发请求（0.65.0起游客、账号通道各自暂停，见[ADR-117](117-ranking-session-refusal-and-row-order.md)）；
  - 不自动重试，失败结果不缓存。
- **结果可见**：
  - 页面显示“B站暂时限制了访问（风控 -352），约 N 秒后可重试”；
  - “帮助与诊断”另起一行，写“最近一次分区/UP投稿读取：账号会话/游客 · 成功/B站返回 N/HTTP N”。只用固定词与整数。
- **继续观看与本机播放队列**：
  - 也打开完整详情页，各自的操作放在页上：
    - 继续观看：按分P续播，并有“删除本机此项”；
    - 队列：主按钮“从本项开始播放队列”，另有“只播放此项”、上移/下移、“删除本机此项”，不显示“加入本机队列”。
  - 原操作逻辑抽成共用函数，旧面板与新页面都调用它。
- **焦点**：任何一次读取完成后，如果焦点丢失（`BODY`、已脱离、隐藏或禁用），依次移到第一张卡片、“重试”或当前选中的来源按钮。

## 不做

- 不伪造浏览器指纹，不使用其他客户端的密钥或ticket，不用通用串伪装。
- 游客侧的访客cookie（`buvid3`等）和WBI签名，等风控恢复后做一次约5个请求的对照实验，再决定。
- 不自动重试。

## 证据

- 原生主机测试`tests/native/public-read.test.py`，10条：继承VOD读取通道的全部检查；正常路径是身份核对、分区、UP投稿；分区编号、mid/page越界和CDN/playurl/视频信息请求都无法开始。原`vod-api`、`pgc-read`、`source-failover`、`catalog-ua`测试仍通过。
- 单元`tests/unit/public-read.test.ts`：复用10分钟；拒绝后暂停60秒且期间不发请求；失败不缓存；帮助文本；请求必须带账号；结果只含卡片、投稿或整数。
- 合成UI`tests/product-up-fix2-ui/fix2.spec.ts`，4条：
  1. 登录后分区走账号会话，不走匿名通道，帮助中有记录；
  2. -352时显示代码，暂停期间切换分区不发请求；
  3. 游客在10分钟内再次打开同一分区只读一次；
  4. “继续观看”“本机播放队列”打开完整详情页并带各自的操作。
  - 4条对冻结0.51.1全部失败。
- 旧规格按版本调整：
  - 0.51.0/0.51.1的限频文字与“重新读取”断言按版本区分；
  - ADR-104焦点测试改为断言“重试后焦点仍在可见控件上”。加严后对0.51.1失败，正是上面说的焦点问题。
