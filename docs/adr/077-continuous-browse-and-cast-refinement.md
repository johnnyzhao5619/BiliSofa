# ADR-077：连续浏览、关注视频目标与完整队列控制

2026-10-22；U2/U3体验修正、F02–F06/F12/F20。用户确认0.34.0 A–F功能组通过，同时提出五项具体体验问题；该通过事实不关闭这些缺陷。本轮0.35.0只完成这五项组合优化，U4账号互动/会话恢复、U5和完整产品验收保持OPEN。

## 五项决定

1. 侧栏向右每次解析真实可见、可用的内容目标。旧锚点在隐藏的“继续观看”中时，改用当前页面入口；导航与正文仍共用实际DOM焦点、既有InputRouter和返回栈。
2. 关注更新DTO允许可选的严格BV标识，播放复用当前身份的点播工作区和本机位置。仅type=8且BV有效的源条目可播；接受源端bvid或严格限定www.bilibili.com/video/BV的uri/jump_url，冲突不播放；专栏和无ID摘要只读。原链接、私密游标、账号凭据仍不进入UI/普通存储/诊断。此处替代ADR-047“所有ID都不跨UI”的旧限制，只开放公开视频标识，不能用标题搜索首项冒充目标。
3. 首页、统一搜索、关注/已追、我的/收藏内容共用ContinuousGrid。接口每批四项保持，前端自动续接，移除常规上一页/下一页操作。仅挂载三批/最多十二卡，移出窗口释放封面资源，向上回读前批；按实际内容ID保留焦点。所有请求仍有源端终点和原查询范围，不能称一次下载全部或无限内容；资源窗口不冒充源端总数。追加失败保留已读内容，无自动失败循环。切来源取消旧读并拒绝迟到结果；预取不锁死卡片操作/栏目选择。
4. 当前产品队列直接使用完整vodWorkspace，不再挂旧四按钮控制器。保留不可变BV＋P顺序和逐P位置；下一项等待当前modal的真实媒体/transport双关闭后再打开，连播决定显式传递。轨道回退、倍速、字幕弹幕、评论、更多、隐藏和返回共用点播合同；旧队列实现仅为旧构建保留。队列循环仅支持当前项，不把视频分P列表的循环误称队列循环。
5. 投屏目的页默认“接收未开启”，明确开始后才创建接收器。等待区显示BiliSofa与手机操作步骤，播放控制仅在媒体状态合适时显示；停止等待下一段、连接结束后可恢复或结束，资源关闭未知不可重用。沿用官方App内TV兼容路线，不新增AirPlay协议、后台唤醒或电视/手机账号关联。Home、控制权和更换手机授权合同保持。

## 布局和证据

[布局/一手参考与取舍](../design/CONTINUOUS_BROWSE_AND_CAST.md)明确借鉴Samsung/Google TV的方向导航和焦点滚动、Netflix返回导航、Apple投屏引导；不宣称复制当前YouTube或B站TV全部UI。

284模块检查、632单元/合同、8项新组合UI＋13项保留播放/设置UI、6项新包负例通过。覆盖空续播、窗口前后裁剪、失败保留与焦点恢复、视频/UP结果续接、私人/本机列表、关注有效目标/专栏边界、队列完整控制/下一P及投屏等待/播放/结束。早期焦点回抢、快速预取漏加载和过时“四卡固定”夹具断言已修正，失败日志保留；合成账号播放夹具补齐身份核对，没有真实账号POST。

[配对证据](../design/evidence/2026-10-22-browse/README.md)记录源码、包及平台安装启动；0.28–0.34冻结工件189文件未变，17原生模块/68项资源含CA沿用。打包只新增明确0.35.0输出/签名部署指针，不扩大权限/网络域。首轮设备能力查询关闭，按原授权地址有界重连一次后state/capability/install/launch明确成功；不是新UI真实声画/Voice Guide/性能验收。[本轮五组清单](../CURRENT_DEVICE_TEST.md)待用户反馈。
