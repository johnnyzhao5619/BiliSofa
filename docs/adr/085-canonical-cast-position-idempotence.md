# ADR-085：当前SOAP整数秒位置的幂等定位

2026-10-22；F20/W06/U4/R11，0.43.0候选，保留0.41/0.42冻结失败和分项通过。

## 证据

0.42.0已避免先pause再重建，但用户看到约1秒→4秒的向前跳转；约64秒主动关停，无自动停播。相同脚本hash的调试记录：SDK实际2080ms收到目标2000ms，执行一次原生Seek后SDK从2546ms→5150ms推进，未再次open/prepare。SDK如何选择该落点未知；[派生摘要/USER边界](../design/evidence/2026-10-22-cast-seek/USER_ACCEPTANCE.md)保留用户近似秒数与SDK精确值，不强行等同。本轮后续控制组未测。

当前产品SOAP GetPositionInfo的RelTime以floor(ms/1000)格式化为整秒；此时2080ms对外就是2秒。对同一2秒再做定位没有新增对外位置意图，却可能触发不连续。这是协议表示精度下的幂等性，不是“首次几秒、偏差多少”的经验容差。

## 决定

- 只在0.43产品当前SOAP接收器中，合法owner/代次/递增命令、非busy、playing、已知时长且有最近1000ms内观察到变化的真实正值tick时，若目标为整数秒并与当前floor(time/1000)相同，直接完成该定位，不调用SDK/pause/open/play，不改写真实时间。期限1000ms是观察新鲜度，不能把陈旧缓存当当前位置。
- 本规则独立于“首次起播”：后续等价定位同样幂等。小数目标、另一整数秒、已暂停、无实际正值tick、陈旧缓存或时钟倒退均正常执行/按原合同拒绝；真正跨秒续播、主动回0在别的秒、Stop/Play和源代次保持。
- 记录seek_current_position，区别SDK成功/真实目标命中。ACK及完成只表示规范化位置已满足，不制造SDK调用或目标tick。原忙态/失败关闭/代次/30秒期限与暂停策略保持；不重放、不延租、不改URI/TLS/账号权限。
- 0.42播放态非零原生路径保留；0.41近零容差在本候选仍不启用。旧探针不启用新规则；未来其他协议/更细时间精度须显式审查，不能直接复用SOAP整秒假设。

## 验证与出口

合成先用冻结0.42与实测边界复现等价2秒Seek跳至5150ms；新候选应没有SDKSeek/暂停/重建、真实tick连续。覆盖真正30秒与回0、暂停同秒/继续、陈旧/小数目标、不同秒、owner/busy、失败和Home。仅完成本地后签名部署并补受影响首投/定位，不重复账号、旧整组或长播。真机未反馈前不宣称首投已平顺或完整F20已通过。
