# ADR-019：单条范围读取超时与媒体会话错误分层

日期：2026-10-16（America/Toronto）。W01/G1、F06/F20。状态：0.0.59候选，325不同相关本地检查通过，已安装并匹配启动/清理报告；G1最小播放路径USER PASS及g2换源/清理匹配；本轮未触发隔离支路，其TV行为未验证。六组W01边界保持。

## 证据与限定

058用户P1→P2后约3秒停播；匹配报告206/28、两个活动本机HTTP客户端、无新代次接受和无精确CDN节点命中。它不能判断超时客户端是否仍被decoder使用，也不能确定新P的身份。旧失败完整保留。

源码路径：任一bridge客户端读错误都调用全局BRIDGE:issue，Worker立即invalidateReceiver，UI stopCandidate。两条并行读取中，一条已收206但停滞、另一条仍真实向decoder传送媒体正文时，也会如此。新增HOST双真实socket/cURL夹具（一个停滞range，一个正常open-range）在058处理逻辑上确实得到BRIDGE:issue:206:28，证明该错误分层缺口；不是本次TV原始请求重放，也不宣称已解释所有早停。

最初夹具未滤掉正常request进度而先失败，修正有界读取ACK后才取得上述故障；两份失败日志都保留。首次TS检查另发现新增可选字段不符合exactOptionalPropertyTypes，已改显式undefined类型，不放宽编译配置。

## 候选行为

1. 原有匿名GET有限续读/重连先执行，不加次数、不延网络15秒无进展/源签名/媒体租期。
2. 重试策略无法继续后，只在渐进媒体、已校验206/范围、真实源总长、清理状态正常，且另一同源活动range最近2秒实际成功向本机decoder发送过正文时，允许结束这一条失效请求而保持其他请求和receiver。只有响应头、相同连接、旧数据、无有效range或所有读取都停滞时仍走原全局失败。TLS、403、错误范围/总长、未知关闭、预算耗尽不进入该支路。
3. 每源最多隔离一次；下一次仍按原全局失败。原累计字节/窗口/连接/retry和会话期限不重置；没有新网络访问、备用地址、HTTP回退或对账户写操作的重试。
4. 原生只输出固定BRIDGE:request_timeout:1。Worker转成带本次媒体代次的cast.media_timeout_isolated_g1..g4，额外最多4条IPC，916→920；不撤销receiver，也不把它称为已恢复。
5. UI必须有当前generation、实际playing且非seek的已发布快照，否则仍按206/28结束。具备条件时，观察真实媒体时间，至少1秒墙钟和1秒真实媒体推进才记录timeout_progress。此为时间事实，仍不是声画USER PASS。整个源保留5秒无实际推进监视，防止先消耗少量缓存后永久冻结；暂停/正在seek时暂停此监视，由原有操作deadline与原授权期限约束，恢复playing后重新计时。没有新增SDK调用、造tick、强制play/pause或延长任何原生期限。
6. 若5秒playing无真实推进，记录timeout_unconfirmed和原media_issue_206_28，停止/清理。后续SDK错误、另一媒体错误或关闭未知继续走原路径。Stop/Back/Home/换源会取消监视；旧计时器不能关闭新源/新会话。单次确认进度后也不能关闭监视而遗留后续卡死。

报告仍8条/4096字节，保留实际FAIL、源决策/退出缓存状态、换源阶段、隔离后进度/未确认与关闭结果；原始URL/请求/字节偏移和对端地址不出IPC。

## 验证范围与设备结束条件

本地只验证受影响功能：HOST bridge的并行读取、bodyless双停滞、每源一次额度及原范围/重试/背压/清理；cast-source累计预算/旧token/换源；真实Worker+UI保持连接后换源、无进度关闭、先有进度后停滞关闭、暂停超过5秒/继续、Home取消无晚到失败，以及原有cast/media用例。strict TS/C、实际Samsung两种链接和最终包输入/许可门禁照常执行，未重跑无关IME、Voice Guide或TLS证书矩阵。

候选通过本地门槛并安装后，G1人工仅同一短UGC：正常P1→切一次P2→新内容正常声画30秒→手机停止/Back开诊断。核对本版报告中的源接受/换源阶段、是否实际触发隔离分支及最终清理；本轮若没有触发隔离，成功也不能证明该分支已在TV验证。失败保留实际阶段，不追加连续三跳/长播。若同问题两轮无新增证据，按W01_EXIT_CHECKLIST停止重复人工操作、转本地/具体阻塞。
