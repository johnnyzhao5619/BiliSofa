# ADR-034：媒体失败保留来源与阶段

日期：2026-10-18。W02/F02/F06，补充ADR-030、032、033。

0.5.0新ID用户确认焦点、成功视频续播、Home停声及设置重开；首张卡在获取播放源失败，换另一张卡才成功。没有该视频的公开ID或原生失败码，不能把猜测当根因。已发现上层丢弃现有Worker闭合结果中的错误码，导致所有取源失败同文案。

采用严格的MediaFailure合同：固定phase、DomainError reason、可选既有ugc失败码。只有source阶段允许ugc码；只取已经规范化的原生/HTTP/API分类，不带标题、BV、CID、URL、token、账号、SDK原文或完整响应。其他媒体阶段目前只保留固定原因，不冒充已有SDK细节。

GuestPlayback保留闭合失败摘要，MediaSession在清理前缓存首个失败，并在decoder/native双关闭后交给应用。显式Back/Home不产生伪失败，取消后的迟回包不改写已完成会话。异常的诊断getter/observer不得阻止清理；状态、真实tick、prepare/seek时限、源刷新政策、权限及网络目标均不改变。

失败反馈区保留具体脱敏码，并区分当前游客路径不支持与可重试网络错误；设置中的本次进程诊断加入同一合同字段，仍最多32条/8条一页、无持久化/上传。未增加账号写请求或自动重播/重试。内部0.5.1只补这条取证/反馈，真实首张失败是否为内容限制、CDN、响应或传输问题仍需一次精确报告或公开样本证明。

已通过的0.5.0观察不重跑。新包完成本地故障注入/来源门禁后，只核对失败卡的取源原因；若当前卡已换且不能重现，记录未复现，继续不受影响的账号/投屏装配验证，不无限寻找失败样本。
