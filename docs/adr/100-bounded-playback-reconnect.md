# ADR-100：播放中网络中断的有界自动重连

2026-10-23；F06/F17、R13、U5。接0.50.1真机结果：P1′ USER PASS；P4′的失败摘要原因为`network`，且时好时坏，同一集先能播、之后又提示网络中断（伍六七之玄武国篇前三集）。仅在`--product-reconnect`（0.50.2）构建生效。状态：**0.50.2已签名并升级安装/启动（平台确认，不清数据）；真机P4″ FAIL，原因与后续见文末与[ADR-101](101-cdn-failover-to-bilibili-backup.md)**（[证据](../design/evidence/2026-10-23-reconnect/README.md)）。

## 原因判断

- B站接口本身返回了播放地址（失败原因不是`permission`或`login`）。失败出在播放源读取或分段传输中，并且随时间变化。这是海外环境下单个CDN节点时断时续的典型表现。
- 现有处理：
  - `VodCatalogMedia`在`prepare`/`playback`阶段遇到`network`/`timeout`时，会在同一视频的其他画质与音轨组合之间回退，最多4次，并保留上次观看位置；
  - 但每个组合使用同一次取到的播放地址；回退用尽后整段播放就结束，不会重新向B站取地址。
- 匿名核对（ADR-099文末）显示主地址多为海外节点，现有地址规则可接受。没有证据表明需要放宽原生CDN白名单，所以不改原生。

## 决定

- 回退用尽、会话确认关闭、且原因是`network`或`timeout`时，播放器自动重连同一集：
  - 清掉缓存的播放源，重新向B站读取地址（可能分到其他节点）；
  - 从最后观察到的位置往前2秒继续；
  - 两分钟内最多2次，等待分别为1.5秒和3秒；
  - 画面显示“网络波动，正在重新连接…（n/2）”。
- 第三次在两分钟内失败时，显示原有的“网络连接中断，播放未完成，可返回后重试”，不再重开。
- 关闭未确认、无权限、登录失效、格式不支持等原因不重连。Back或离开播放会取消已排定的重连，旧会话的晚到回调按代次丢弃。
- 诊断记入固定代码`reconnect_scheduled`，便于与失败摘要对照。

## 证据

- 单元`tests/unit/media-reconnect.test.ts`：只对已关闭的网络或超时失败重连；有上限；退避；两分钟后重新计数。
- 合成UI`tests/product-reconnect-ui/reconnect.spec.ts`：
  - 一次掉线先经画质回退，再重连；在原位置之前继续，且不显示终止错误；
  - 两次重连后第三次停止，并显示原有提示、不再重开。
  - 两条对冻结0.50.1均失败。
- 汇总见[证据](../design/evidence/2026-10-23-reconnect/README.md)。真机复验待用户。

## 0.50.2真机结果（P4″，2026-10-23）

- 伍六七之玄武国篇前三集仍然失败：画面两次出现“正在重新连接…（1/2）”，随后停止并显示原有的“网络连接中断”；每次出错位置一致。其他视频可以播放。
- 更正上文“没有证据表明需要放宽原生CDN白名单”：匿名核对显示，主地址节点在固定偏移之后回源失败；而B站给出的备用地址（Akamai）可以完整读取，只是一直被地址规则丢弃。重连拿到的仍是同一主机，所以无效。
- 处理见[ADR-101](101-cdn-failover-to-bilibili-backup.md)：按轨道切换到B站备用线路。本ADR的有界重连保留，作为最后一层。
