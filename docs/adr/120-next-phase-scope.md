# ADR-120：下一阶段纳入列表稳定、小数倍速、多账号登录与设置布局

日期：2026-10-27。关联 F02/F04/F05/F06/F12/F13、W02/W03/W04/W07。状态：范围与实施计划中的决定均已由用户确认（2026-10-27），见[实施计划](../plans/2026-10-27-next-phase-plan.md)“已确认的决定”；尚未开始实施。

## 用户决定

除收口台账中已有的剩余项外，下一阶段实施还包括四项：

1. 解决列表刷新时随意跳动的问题。
2. 实现0.25×、1.25×、1.5×、1.75×倍速。用户指出这不是设备能力问题：同一台电视上的YouTube等应用可以小数倍速播放。
3. 多账号登录。
4. 优化设置页的界面布局。

## 对既有决定的影响

- **[ADR-069](069-single-account-current-delivery.md)**：其“当前版本跳过真实双账号功能与验收”由本条取代。F13不再是用户排除项，多账号登录、切换、移除及其数据隔离进入交付与验收范围（R18）。ADR-069中保留的隔离、代次与旧请求取消机制继续作为实现基础。
- **历史ADR-097“小数倍速为本机设备限制”**（[固定提交原文](https://github.com/johnnyzhao5619/BiliSofa/blob/a709767e0fd4b6eef741bd3193bafa6348ca0ff8/docs/adr/097-fractional-rates-device-limited.md)）：当时只测了HTML `<video>`直接播放本地DASH清单这一条路线（0.25×停住，1×以上实际约1.1–1.2×封顶）；AVPlay本身的小数`setSpeed`从未在本机试过。该结论因此只适用于那条路线，不再作为“本机不能小数倍速”的产品结论。R17重新打开：先在本机证明可行路线，再接入生产菜单；不可用的档位不进入菜单。
- 列表稳定（R16）与设置布局（R19）是交互质量要求，不改变F02/F12的功能范围。

## 不变

- 直播仍按[ADR-068](068-current-scope-and-reversible-interactions.md)排除；评论与弹幕仍只读（ADR-003）。
- 签名、部署按版本授权；真实账号写入须具体授权；多账号验收所需的第二个真实账号由用户提供并在验收时授权使用，不在仓库或日志中保存任何凭据。
- 设备结论只来自本机实测，不由其他应用、API列表或模拟器推定为本应用已通过。
