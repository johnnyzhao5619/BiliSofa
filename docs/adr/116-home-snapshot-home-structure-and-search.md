# ADR-116：首页快照持久化、首页结构、去掉重复入口、搜索综合结果与词典常驻

2026-10-26；F02/F03/F05/F07、R05/R12、性能与交互。接2026-10-25 review第2.3、6.3、6.4、6.5节与ADR-108/109/113。状态：**用户已确认全部决定（2026-10-26）；0.64.1已安装，用户实看通过**。改动方案见[P2b方案](https://github.com/johnnyzhao5619/BiliSofa/blob/6e327470c9f8d6814cebe0e5796b01f81bd9534e/docs/archive/2026-10-26-plans/2026-10-26-p2b-home-search-plan.md)。

## 背景

对照review与当前代码（0.63.0）：

| 项 | review建议 | 当前代码 |
| --- | --- | --- |
| 首页快照 | 热门、排行首屏与热搜写进本机存储，冷启动先画上次的首页，后台再刷新 | 没有持久快照。每次进入首页（含从别页返回）都按顺序重新读取各货架，读完前是骨架卡；`public-lists.ts`只有进程内10分钟缓存，且只覆盖分区与UP投稿 |
| 重复入口 | 账号页不再重复“稍后再看/云端历史/收藏/关注更新/追番” | 已在0.62.0完成：这些按钮本就不显示，已随账号并入设置删除。剩下两处死代码：<br>① `product-page.ts`里`route.page==='search'`的旧搜索分支，因`discoveryEnabled`恒为真而走不到，连带`productHome`的搜索模式、`user-search.ts`、`pgc-search.ts`（各自一套关键词弹窗）；<br>② `libraryEnabled`/`discoveryEnabled`/`collectionsEnabled`三个恒为真的开关 |
| 首页结构 | 继续观看→为你推荐→热门→排行榜→分区横排快捷入口（不弹窗）；网格页去掉上一页/下一页；行尾自动加载更多 | 分区只能从末尾“浏览分区”进入：先打开“查看更多”网格，再弹出分区选择。<br>首页、我的、关注三页的上一页/下一页在连续滚动下已隐藏，但按钮与`if(!feed)`分支仍在。<br>货架每行最多12张卡，行尾只有“查看更多” |
| 搜索综合结果 | 默认“综合”：前几条视频、一行UP主、一行番剧 | 只有视频、UP主、番剧影视三个类型，分别读取 |
| 搜索词典 | 应用级常驻，空闲时预加载 | 每个搜索键盘新建一个Worker，并重新解析约1 MB的`search-words.json`。离开页面会销毁；清空已输入的字母时也会销毁，下次输入再解析一遍 |

## 决定

### 1. 首页快照持久化

- **存什么**：只存卡片元数据（编号、标题、UP名、时长、播放数、封面引用），不存Cookie、地址参数或任何会话信息：
  - 热门、排行榜两行各最多12张；
  - 热搜词最多10个。
- **存在哪**：
  - 公共快照：`localStorage`一个键，所有身份共用；
  - “为你推荐”：按账号分区单独存；移除该账号、或在设置里清除本机数据时一并删除。
  - 两者都有体积上限（公共约32 KB），读回时按合同逐项校验。外来文本只当数据，校验失败就整份丢弃。
- **何时用**：
  - 冷启动或进入首页时，快照不超过24小时就先画出来，不再显示骨架卡；
  - 随后每行在后台读一次，仍按现在的顺序队列，不增加请求数；
  - 读到后原位替换：焦点卡片若还在，焦点留在它上面；否则留在同一位置。
- **刷新失败**：保留快照里的卡片，这一行的状态写“显示的是上次的内容”，不显示失败行。
- **同一次运行内返回首页**：上次读取不到5分钟的行直接用内存结果，不重读。超过5分钟则先显示、再后台刷新。

### 2. 首页结构

- **分区横排**：排行榜下面加一行14个分区按钮（动画、游戏……动物），按OK直接进入该分区的“查看更多”网格，不再弹窗。首页末尾的“浏览分区”去掉；网格页“分区”页签的选择弹窗保留。
- **行尾自动加载**：焦点到达一行最后一张已加载的卡片时，在“查看更多”之前追加下一页。
  - 热门每行最多3页，排行榜的100条一次读完、按12张分批显示；
  - “为你推荐”不追加，避免多拉账号推荐；
  - 一次只追加一页。
- **继续观看**：仍只用本机记录。与云端历史合并需要在首页启动时多一次账号读取，而云进度按用户决定跳过，所以不在这一批做。
- **翻页按钮**：删除首页、我的、关注三页已不显示的上一页/下一页按钮与`if(!feed)`分支。刷新按钮仍只在失败或空列表时出现，这一点不变。

### 3. 去掉重复入口与旧搜索分支

- 删除`product-page.ts`的旧搜索分支、`productHome`的搜索模式、`user-search.ts`、`pgc-search.ts`，以及三个恒为真的开关和它们守护的死分支。
- 删除前逐个确认没有其他引用，测试随之调整。
- **“关注”页的“我的追番 · 我的追剧 → 番剧影视”直达卡保留**：这是用户在ADR-103要求并验收过的捷径，不算重复入口。

### 4. 搜索综合结果

- 类型页签最前面加“综合”，作为新的默认：
  - 第一页视频，与现在的视频网格相同；
  - 一行UP主，最多4个；
  - 一行番剧影视，最多4个。
  - 后两行各带“全部”，按下切到对应页签。
- **请求顺序**：先读视频；视频结果画出后，再依次读UP主和番剧（不并行）。每个新关键词因此多两个请求，换来一屏看到三类。切换页签与翻页仍复用同一关键词的快照（ADR-108），不重读。
- UP主或番剧读取失败、或没有结果时，这一行不显示，不影响视频结果。
- 不用B站的“综合搜索”接口：那要给常驻公共内核加新的原生接口并重新链接，这一批不动原生。

### 5. 搜索词典常驻

- 应用只保留一个词典Worker，首页显示约3秒后、浏览器空闲时预加载。
- 首页搜索、字幕弹幕设置等所有拼音首字母键盘共用它。离开页面和清空字母都不再销毁，应用退出（pagehide）时才关闭。
- 它不联网；切到后台时保留。
- 内存约多几MB（词典已解析的结构），换来进入搜索、输入第一个字母时不再等待重新解析。

- 不改原生，原生资源与0.63.0逐字节相同。
- 新增本机存储键只有两类：公共快照、按账号的推荐快照。

## 实现（0.64.0）

| 决定 | 实现 |

| 1 首页快照 | 新合同`packages/contracts/src/home-snapshot.ts`（逐项校验，卡片沿用`parsePopularCard`，热搜沿用`parseHotSearchTerm`，32 KB上限，时间不得在未来）与存储`apps/tv/src/platform/home-snapshot-store.ts`。公共键`bilisofa.home-snapshot.v1`，推荐键加账号编号；任何读写失败都按无快照处理。货架挂载时有快照的行立即画出，首页的初始焦点就是快照第一张卡；后台读取仍是一行领先的顺序队列。读到后若卡片相同则不重画，不同则原位替换，焦点留在同一张卡或同一位置、横向滚动位置不变。刷新失败且有快照时显示“显示的是上次的内容”，不出现失败行。同一次运行5分钟内返回首页直接用内存结果。热搜面板先显示上次的词，再刷新；刷新后焦点不被拉回第一项 |

## 设备验证（0.64.0）

[证据](../design/evidence/2026-10-26-p2b-device/README.md)。登录状态，每次新启动，Inspector发键，各3次。

| 指标 | 0.63.0 | 0.64.0无快照 | 0.64.0有快照 |
| --- | --- | --- | --- |
| 选账号OK→首页第一张卡 | 约2.35 s | 约2.44 s | **约1.96 s** |
| 进入搜索→首个候选 | 约0.59 s | 约0.19 s | 约0.13 s |
| 再次进入搜索→首个候选 | 约0.56 s | 约0.11 s | 约0.14 s |

- 有快照时首卡早约0.4 s。剩下约1.8 s推测主要是选账号后的身份核对与页面建立（未分段计时）：冷启动的大头不在列表读取，快照对这一段帮不上。
- 词典常驻让首个候选快了约0.4 s。
- 用户实看首页快照与更新、行尾追加、分区直达、搜索综合与“全部”、候选速度，全部符合。

**0.64.1修正（用户发现）**：

- **问题**：排行榜还在加载、只有骨架卡时，焦点在“分区”行按上键不动，跳不到上面的热门视频。原因是上下键的目标只看紧挨着的上一行或下一行，而加载中的行没有可停的按钮。
- **修正**：上下键越过没有按钮的行，落到最近一行有按钮的行；“继续观看”往下同理，取第一行有按钮的货架。页面初始焦点仍只落在第一行货架的卡片上。
- **测试**：新增合成测试“加载中的行被越过”，只扣住排行榜的读取，让它停在骨架卡状态。这条测试在原来的连线下失败，修正后通过。
- **设备**（0.64.1已安装，[证据](../design/evidence/2026-10-26-p2b-device/README.md)）：热门已读完、排行榜仍是骨架卡时，受信任按键从分区按上到热门视频、再按下回到分区。
- **另发现**：排行榜在设备上加载了一分多钟后以`timeout`失败。已查明：超时是测试脚本扣住请求所致，真实原因是B站对匿名全站排行返回-352，见[ADR-117](117-ranking-session-refusal-and-row-order.md)。

## 不做

- 继续观看与云端历史合并（云进度按用户决定跳过）。
- B站“综合搜索”接口与原生改动。
- 封面缓存策略调整（review 2.3的封面四项已由ADR-109部分处理，另行评估）。
- 焦点系统（review 6.6）。

## 验收与证据

- **单元**：
  - 快照的写入、读回校验、24小时过期、体积上限、账号分区与清除；
  - 原位替换时焦点的规则；
  - 词典Worker单例的生命周期（不随页面销毁、pagehide关闭）。
- **合成UI**：
  - 有快照时首页立即显示卡片、无骨架，刷新后原位替换且焦点不跳；
  - 刷新失败时保留快照并提示；
  - 分区横排按OK直达网格；
  - 行尾追加一页；
  - “综合”页三段与“全部”；
  - 离开再进入搜索不新建词典Worker。
- **设备**（签名安装需逐版本授权）：
  - 冷启动到首页第一张卡出现的时间：0.63.0对比0.64.0，有快照与无快照两种；
  - 进入搜索后第一个字母到候选出现的时间：首次与再次；
  - 首页、搜索、分区直达的实际观感。

## 风险

- **快照过时**：超过24小时不用；刷新失败时明确提示“上次的内容”，不冒充最新。
- **本机存储**：推荐快照属于账号的私人数据，按账号分区，并随账号移除与“清除本机数据”删除。读写失败时不影响首页，直接按无快照处理。
- **综合页多两个请求**：在风控敏感的时段可能触发限流。按ADR-105沿用现有的节制与暂停规则；UP主、番剧两行读取失败只是不显示。
