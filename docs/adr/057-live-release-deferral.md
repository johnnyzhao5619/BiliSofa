# ADR-057：用户批准直播延期与W04收尾边界

状态：2026-10-20，已接受。依据用户最新指令：“直播问题可暂缓解决，将其放置之后版本功能”。这是直播范围的明确版本调整，优先于原单一v1.0.0全功能约定；不是直播验收通过。

## 范围

- 直播播放、直播画质切换/断流恢复及依赖实播的F16直播弹幕、F20可投直播分支延期至后续产品版本；版本号、日期尚未确定。
- 保留F18编号、代码、冻结工件、失败和已通过的直播搜索/推荐/关注/分区浏览结果。此次不删除入口、不卸载或清数据；后续发布界面须明确未交付的直播播放状态，不宣称支持。
- 点播、PGC、点播弹幕/评论和官方三端的非直播投屏不延期；其他F/W缺口不因本决定自动通过或移出范围。评论/回复/弹幕继续只读，不增加外部常开服务。
- 停止本轮直播探测、换房间、修复包部署及用户配合测试。后续恢复开发须有新的可执行网络排查依据；先解决清单HTTP阻塞，再验收声画/画质/恢复/消息，不重做无影响的点播项目。

## 已确认故障与图层排查

0.21.4用户实机反馈规范化为`live.network.source.manifest_h0_c28_n2`：第2个实际CDN候选的清单请求未收到HTTP响应，cURL28超时。失败在source阶段，尚未创建解码会话；能定位失败层次，不能唯一确定CDN、网络路径或服务端拒绝中的根因。[ADR-056](056-live-cdn-startup-and-evidence.md)的候选策略没有解决本轮实际故障。

代码核查：`LivePlayback`在源/中转就绪后才创建`MediaSession`；播放态的`playing-media`显示`#av-player`并隐藏原页面和inert父面板，控制条仍覆盖底部。准备/源失败时播放器对象隐藏。这解释了本轮“只有控制条”，不是已证实的播放态图层错误。

新增现有浏览器用例的图层断言，2项定向检查通过：合成起播时播放器可见、父页面隐藏且画面区域命中播放器对象；合成同码源失败时解码器打开次数为0。日志`.local/w04-214-layer-review-final.log`。只证明DOM/CSS和控制流程，不证明真实直播解码图层；该实机疑点随直播延期保留。未修改运行时代码、重建或部署新包，电视仍为原0.21.4。

## W04结论

**开发整包已交付，不能标记W04全项验收完成。** 后续用户要求阶段收口并启动W05，执行责任调整见[ADR-058](058-w04-closure-and-w05-start.md)；以下缺证保留，不再要求补测旧包。 A–C、D关注/分区已请求组及点播跨内容回退保留USER PASS。直播改为DEFERRED，不再是本轮阻塞。非直播剩余按[收尾表](../archive/2026-10-24-phase-records/W04_DEVICE_ACCEPTANCE.md)核对：E当前整包生命周期/独立运行、F17真实追番写回/回读；HDR/独立decoder及未覆盖样本保持条件缺证。30条/两小时压力与完整设备矩阵归W07，不增加本轮测试轮次。
