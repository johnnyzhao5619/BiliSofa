# ADR-113：P1-2交互精简——卡片直接播放与长按菜单、续播不再弹窗、播放器快捷设置条、导航收拢

2026-10-26；F01/F05/F06/F07/F08/F12、R01/R03、交互。接2026-10-25 review第六章与ADR-110“不做”。状态：**用户确认（2026-10-26）：第1项按用户修改为“OK直接播放、长按卡片调出菜单”，播放器不加“详情”按钮；第2–5项按方案。P1-2a（第1–3项）在0.60.0实现并已签名安装，设备实按与按键数表一致（见“P1-2a设备实按”），另有两处待修。P1-2b（第4–5项）未开始**。改动方案见[P1-2方案](../plans/2026-10-26-p1-2-interaction-plan.md)。

## 背景

review第六章把“操作繁杂”归到几个高频操作上。按当前代码核对（2026-10-26，按键数从焦点已在目标卡片或播放器上算起）：

| 操作 | 今天的按键 | 原因 |
| --- | --- | --- |
| 首页卡片→开始播放 | 2（OK进详情，OK播放） | 所有卡片都先进整页详情（ADR-091/104/105） |
| 有进度的视频从头播放 | 3（OK，右，OK） | 详情页“从头播放”是第二个按钮 |
| 本机队列从某项开始播放 | 3次以上，外加一个续播弹窗 | 详情→“从本项开始播放队列”→播放器里问“是否继续本分P上次的位置？” |
| 播放中换分P（上一P/下一P/选择分P），目标有进度 | 多一个弹窗“继续X的本机进度？” | `vod-change-resume`（`vod-workspace.ts:193-202`） |
| 播放中换画质（控制层隐藏时） | 7+k到13+k | 唤出→右移N次到⚙→OK→画质→k次方向→OK；N随登录状态与是否多P在4–9之间 |

其他发现：

- **导航**：侧栏有8项：首页、搜索、关注、番剧影视、我的、投屏、账号、设置。“账号”页实际只剩账号管理；“设置”里已有一项“查看账号与登录”跳到“账号”。
- **重复入口**：只存在于源码里。“账号”页的“稍后再看 · 只读”等五个按钮被`productAccount`重排时丢弃，从未显示；`product-page.ts:140-145`的备用资料库列表、`guest-home.ts`也不会被用到。
- **工程化文案**：仍会显示给观众的有：
  - “账号只读”“· 只读”（我的、收藏夹面板）；
  - 删除账号确认里的“防重复写操作记录”，与`TV_PRODUCT_DESIGN.md`的“普通页面不出现防重日志”冲突；
  - 若干“未确认”。
- **自动连播已经有了**：片尾5 s倒计时、默认开启（ADR-090）。`TV_PRODUCT_DESIGN.md`仍写着“自动下一项仅在用户已开连播时触发”，与默认开启不符。
- **按键开销**：
  - 每按一次方向键，焦点路由都要扫描当前层所有`[data-focus-id]`并读取几何；内容区在每次`focusin`时还要再扫一遍；
  - 播放器整个生命周期里每200 ms重写一遍控件的`disabled`、文字和焦点邻居，控制层隐藏时也照写。
- **既有规则与按键**：
  - `TV_UI.md`与`TV_PRODUCT_DESIGN.md`都规定“不依赖数字/颜色/菜单/长按隐藏操作”“按住确认不能多次提交”；
  - 应用只注册了媒体键，输入路由只监听`keydown`；
  - 这台电视在按住OK时是否连续发`keydown`、松开时是否可靠地发`keyup`，还没有设备证据。
  - 用户决定（2026-10-26）：卡片采用长按菜单（参照YouTube电视端），对卡片放开“长按”这一条，见第1项与“取代与修订”。

## 决定

1. **卡片OK直接播放，长按卡片调出菜单。**（用户决定，参照YouTube电视端）
   - **适用范围**：首页货架与网格、搜索的视频结果、UP投稿、稍后再看、云端历史、收藏、关注更新、继续观看、本机播放队列。
   - **短按OK**：
     - 立即播放：有本机进度就从该位置继续，否则从头；
     - 本机队列条目则从这一项开始播放队列（今天详情页的“从本项开始播放队列”）；
     - 番剧影视的卡片照旧进季页（要先选季、选集，季页见ADR-096）。
   - **长按OK（约0.5 s）**：在卡片下方弹出菜单，焦点在第一项，Back收起、焦点回到原卡片。菜单项按卡片类型给出，不可用的不显示：
     - 详情（今天的整页详情：分P、简介全文等）；
     - 从头播放（有本机进度时）；
     - 稍后再看（登录时，加入/移出，沿用现有的先读后写与结果回查）；
     - 加入本机队列；
     - UP主页（选中时用公共内核读一次视频信息取得UP的mid，10分钟缓存）；
     - 本机队列条目另有：只播放此项、上移、下移、删除。
   - **按键处理**：
     - 卡片在松开OK时判定：按住不到阈值就是短按；达到阈值就打开菜单，之后的连发与松开都忽略。所以按住不会重复提交，也不会既打开菜单又开始播放；
     - 其他按钮仍按今天的方式在按下时响应；
     - 指针（智能遥控器的鼠标模式）点击即短按，右键或`contextmenu`打开菜单。
   - **可发现性**：同一身份前3次进入首页时，首个货架标题旁显示“长按OK：更多选项”，之后不再显示。（最初放在焦点卡片下方，实测被下一排遮挡，0.60.1改到标题旁。）
   - **播放器不加“详情”按钮**（用户决定）；播放器主行保持今天的组成。
   - **预读**（ADR-110）：在卡片`keydown`时就开始读取，短按时交给播放器；判为长按时取消。
   - **设备前提（已确认，[证据](../design/evidence/2026-10-26-ok-key/README.md)）**：
     - 这台电视10次按OK全部有`keyup`，按住时完全没有`keydown`连发；短按274–308 ms，按住1938–2840 ms。
     - 因此长按用计时判定：`keydown`开始计时，0.5 s内`keyup`为短按，到0.5 s仍按住就打开菜单，之后的`keyup`忽略。
     - 短按在`keyup`时响应，约晚0.3 s，所以在`keydown`时就开始预读，判为长按时取消。
2. **续播不再弹窗：直接从进度继续，短时显示“从头播放”。**
   - 适用于：卡片直接播放、队列播放、番剧选集，以及播放中切换上一P/下一P/选择分P/合集。目标有本机进度时都直接从进度继续，不再出现“是否继续……”与“继续X的本机进度？”两个弹窗。
   - 首帧出现时控制层自动出现8 s，焦点在新增的“从头播放”按钮上，OK即跳转到0；8 s后控制层收起，焦点回到“暂停/继续”。（0.60.1起；最初在起播命令后就出现，首帧前按会整条重读。）
   - 设置里的“本地续播提醒”改为“自动续播”：
     - 开（默认）：如上；
     - 关：一律从头，同样不弹窗。
   - Home返回后的“继续观看/从头播放”提示（ADR-093）不变：那是主动打扰的场景，仍然不自动播放。
3. **播放器快捷设置条。**
   - 控制层显示时，在主行按↓，打开一排快捷设置：画质、倍速、弹幕、字幕、连播。焦点落在画质上，选项与⚙里相同。
   - ⚙面板保留，其余项不变（编码与音轨、弹幕设置、循环、合集、收藏夹、加入本机队列）。
   - 隐藏层的键位约定不变（ADR-088：上/下只唤出，OK暂停，左右预览跳转）。
   - 控制层隐藏时换画质：↓唤出、↓打开快捷设置条、OK进画质、k次方向、OK，共4+k次。
4. **导航收拢：账号并入设置。**
   - 侧栏从8项改为7项：首页、搜索、关注、番剧影视、我的，下方一组为投屏、设置。
   - “设置”第一组改为“账号”，直接列出当前账号、重新扫码、使用游客身份、获取登录二维码与已保存会话（即今天“账号”页的内容）。
   - 投屏保留在侧栏：手机投屏前需要先在电视上开始接收（ADR-031/064），放进二级页面会让人找不到。
5. **文案与死代码清理。**
   - 观众可见文案去掉“只读”“· 只读”“防重复写操作记录”等实现用语，“未确认”改为说明下一步怎么做（例如“结果未知，请稍后到我的里核对”）；诊断页保留原用语。
   - 删除从未显示的重复按钮、备用资料库列表与未引用的`guest-home.ts`。
   - 同步修正`TV_PRODUCT_DESIGN.md`里“仅在用户已开连播时触发”的旧说法。
6. **按键开销（一并做）。**
   - 播放器的200 ms刷新：控制层隐藏时只更新时间轴与进度记录，控件的文字、可用状态与焦点邻居只在状态变化时重写。
   - 焦点路由：有显式`data-left/right/up/down`邻居时直接跳转，不再扫描整层；内容区的`focusin`不再重复扫描。

## P1-2a实现（0.60.0）

- **长按识别**（`apps/tv/src/ui/input.ts`，唯一的输入路由）：
  - 带`data-hold`的控件在OK按下时不立即响应，开始计时；
  - 0.5 s内松开则`click()`；到0.5 s发出`tv-hold`，之后的松开忽略；
  - 按下期间按别的键、焦点离开都会取消；
  - 按下时发`tv-press`（用于预读），取消或转为长按时发`tv-press-cancel`；
  - 指针的`contextmenu`等同长按。
- **卡片动作**（新的`apps/tv/src/app/card-actions.ts`）：`videoCard()`给出一张卡片的短按与长按，各入口共用：
  - 入口：首页网格与货架、继续观看、UP投稿、搜索的视频结果、我的（继续观看、本机队列、稍后再看、云端历史、收藏）、关注更新；
  - 短按：带本机进度播放，交接按下时开始的预读；本机队列条目运行“从本项开始播放队列”；
  - 长按：卡片下方的菜单（详情、从头播放、稍后再看、加入本机队列、UP主页，加上条目自身的操作，例如队列的上移、下移、删除）；Back回到原卡片；
  - 页面拆除时，未松开的预读由每个页面一个的资源统一关闭。
- **稍后再看**：账号运行时新增`openInteractions(bvid)`，经与播放相同的当前账号与过期检查（`accountInteractions`），打开现有的互动面板（先读实际状态再写一次）。只在登录时出现。
- **UP主页**：卡片只带UP名，选中时经公共内核读一次视频信息取mid（10分钟缓存）。
- **提示**：每个身份前3次进入首页时显示“长按OK：更多选项”（本机存储计数，读写失败就不显示）；0.60.1起放在首个货架标题旁。
- **续播**（`vod-workspace.ts`）：
  - 起播与上一P/下一P/选择分P/合集都不再弹窗，`resumeAt()`给出位置；
  - 有进度时显示“已从 m:ss 继续”与聚焦的“从头播放”，控制层保持显示，首帧后8 s收起并把焦点还给“暂停/继续”；
  - 设置项改名为“自动续播”（存储字段仍是`resumePrompt`）。
- **快捷设置条**（`player-presentation.ts`）：
  - 主行按↓打开一排代理按钮：画质、倍速、弹幕、字幕、连播；每个代理点击原控件，并同步原控件的文字与状态；
  - ↑或Back收起；
  - ⚙面板与隐藏层键位不变。
- **文档**：`TV_UI.md`与`TV_PRODUCT_DESIGN.md`的长按、详情入口、续播、连播与快捷设置条规则已同步。
- **测试**：
  - 单元774/774；
  - 合成UI 105/105：新增`direct-play.spec.ts`（短按直接播放；长按只打开一次菜单且不播放，Back回卡片；按下后移开不触发；快捷设置条）；13条“卡片→详情”规格改为经菜单进入详情；队列续播规格改为断言“从头播放”；
  - 打包负例12/12。

## 0.60.1修正（实按发现）

- **快捷设置条选完就收起**：
  - 打开选择器的项（画质、倍速、字幕）先收起快捷设置条再打开选择器；选完或Back后，焦点回到主行，再按一次Back就收起控制层；
  - 开关项（弹幕、连播）仍保持快捷设置条打开，方便连续切换。
- **“从头播放”只在首帧后出现**：起播期间只记下续播位置，首帧出现时才显示并聚焦“从头播放”，8 s后收起。按它总是一次跳转到0，不再重新读取。
- **长按提示改到首个货架标题旁**：原先在焦点卡片下方，实测被下一排遮挡。

## 按键数（目标）

| 操作 | 今天 | 之后 |
| --- | --- | --- |
| 首页卡片→开始播放（有无进度都一样） | 2 | **1** |
| 有进度的视频从头播放 | 3 | **2**（OK，再OK“从头播放”；或长按→“从头播放”） |
| 打开详情 | 1 | 2（长按，OK“详情”） |
| 稍后再看、加入本机队列、UP主页 | 2–3（进详情再选） | 2–3（长按，移到该项，OK） |
| 本机队列从某项开始 | 3次以上＋弹窗 | **1** |
| 播放中换分P，目标有进度 | ＋1个弹窗 | 不再弹窗 |
| 播放中换画质（控制层隐藏） | 7+k到13+k | **4+k** |

代价：打开详情从1次变成2次，而且要知道“长按”。依据是：直接播放远比看详情频繁。卡片下方的提示与YouTube电视端的同类做法，用来降低“不知道能长按”的风险。

## 取代与修订

- **ADR-091/104/105**：“所有卡片先进整页详情”，改为第1项：短按播放、长按菜单里的“详情”；整页详情本身不变。
- **`TV_UI.md`第18行与`TV_PRODUCT_DESIGN.md`焦点规则“不依赖……长按隐藏操作”**：按用户决定，对内容卡片放开“长按打开菜单”，并以卡片提示降低隐藏性；“按住确认不能多次提交”保持。其他控件仍不依赖长按。
- **ADR-072**：“显式播放不再弹窗”扩大到第2项的所有场景；六个主目的地加次级“账号/设置”改为第4项。
- **ADR-032**：
  - `resumePrompt`的含义由“是否询问”改为“是否自动续播”，存储字段不变；
  - “从本地位置恢复需用户明确选择”改为直接从进度继续，同时短时提供“从头播放”。
- **ADR-090**：⚙面板内容不变，增加快捷设置条。
- **ADR-088**：不变。
- `TV_UI.md`第8行、`TV_PRODUCT_DESIGN.md`信息架构表、详情行与连播说明同步修改。

## 不做

- 菜单键、数字或颜色键操作；卡片以外的长按操作。
- 播放器主行的“详情”按钮（用户决定不加）。
- 自动连播到不相关的推荐视频（只在同一视频的分P、合集与番剧内）。
- 首页结构、搜索混合结果、搜索词典常驻（review 6.4、6.5，另行安排）。
- 视觉与动效（P2）。

## 验收与证据

- **单元**：
  - 续播策略：有进度、无进度、“自动续播”关，覆盖卡片、队列、番剧、换分P；
  - 快捷设置条的选项与⚙一致；
  - 刷新只在变化时写入。
- **合成UI**：改写今天断言“卡片→详情→播放”的规格（`polish-helpers.ts`的`playFromShelf`等约十个文件），新增：
  - 卡片短按直接播放，并在8 s内可从头播放；
  - 长按打开菜单，各项可达（详情、从头播放、稍后再看、加入本机队列、UP主页、队列操作），Back回到原卡片；
  - 按住不重复提交，长按不会同时开始播放；
  - ↓打开快捷设置条并换画质；
  - 设置里的账号组；
  - 侧栏7项。
- **设备**：
  - 先确认这台电视按住OK时的`keydown`连发与松开时的`keyup`；
  - 按上表逐项实按，确认按键数；
  - 在首页与长列表上测连续方向键的响应（与0.59.0对比），确认刷新与焦点改动没有变慢。

## 风险

- **误触直接播放**：浏览时按了OK就开始播放，比进详情更“重”。缓解：
  - 播放器返回一次就回到原卡片；
  - 预读让开始更快；
  - 本机进度照常记录。
- **控制层自动出现8 s**：会短暂遮挡画面。只在有进度、从进度继续时出现，从头播放时不出现。
- **习惯改变与可发现性**：老用户熟悉“先进详情”，长按不容易被发现。靠卡片提示缓解；合成UI与设备验收都要覆盖长按菜单里的每一项。
- **长按识别依赖`keyup`**：已在这台电视上确认可靠。若别的遥控器或设备不发`keyup`，每次按OK都会在0.5 s后打开菜单而不是播放；当前交付只针对这台电视，其他设备需另行确认。
