## 本轮对照的实现事实

- 身份代码 `platform/wasm-network/src/identity.c` 使用 Bilibili 网页二维码生成 / 轮询路线；这描述技术路线，不表示公开 API 或平台授权。
- `apps/tv/src/platform/visitor-id.ts` 保存平台发放的游客标识，使用有效期为 30 天，并有清除入口；游客不等于全程不可关联。
- `packages/bili-client/src/search-wbi.ts` 与原生模块处理 WBI / 接口字段；`tools/package-foundation-app.py` 固定播放、评论、互动和投屏模块的包来源。固定路由及 TLS 校验是安全措施，不是使用许可。
- 评论 / 回复 / 弹幕只读；其他保留互动、投屏前台接收、云进度未完成验收和暂停项见[版本说明](releases/0.65.1.md)。不因本轮风险调研擅自移除功能，也不把历史失败改成通过。

本轮是指定提交的文档与来源审阅，未完成全 Git 历史、所有媒体素材、所有协议路线或所有依赖的法律 / 安全审计，也没有向 Bilibili 发送询问。

## 发布建议

1. 软件许可证保持标准 MIT；把平台与内容权利另列。不要以“仅供学习”“用户自行负责”“24 小时删除”等口号暗示可免除责任。
2. 公开版本明确为 0.65.1 和完整提交，不把它包装成完整 v1.0.0、官方应用、全型号兼容或区域解锁产品。
3. **最需要先解决的是 5.6(3) 与非官方服务获取途径的授权不确定性。** 更好的 README 能减少误导，不能消除此风险；在广泛分发二进制、商用、收费、预装或推广前尤其应取得书面许可 / 专业评估。
4. 按[发布清单](RELEASE_CHECKLIST.md)处理源码历史、素材、实际 WGT、第三方许可和私密报告渠道；使用可追溯附件和哈希，不上传私密签名包。
5. 发生权利投诉或平台明确拒绝时，先保存必要证据、停止受影响的分发 / 功能并核对权利；不把接口对抗或继续换身份当作默认恢复方案。

这里提出的是可执行的风险处理，不是要求重写 MIT 为限制性许可证。是否获得第三方授权应以真实材料记录，不能用维护者自己勾选一个“免责”框代替。
